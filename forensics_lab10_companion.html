Overview — what this lab is really teaching

Not all evidence sits in plain view. Steganography hides data inside another file; Alternate Data Streams (ADS) hide data inside an NTFS file's hidden streams. This lab shows you both — how they're made and, more importantly, how they're detected.

These are anti-forensic techniques. You learn to create them only so you recognize them in the wild: a message appended after a JPEG's FF D9 footer, a whole file tucked after it, or a secret hidden in file.exe:secret.txt that dir won't show but dir /r will.

Don't practice these on real evidence

Appending to a file changes its hash and size and destroys its integrity. Do this only on practice files, never on an evidence item.

Walkthrough

Task 1 — Steganography: a message after the footer

1 Find the end of a JPEG

Open WhatsApp-Encryption.jpg in HxD, jump to the end, and locate the JPEG footer FF D9. Picture viewers stop reading there — so anything after it is invisible to them.

2 Append and save a hidden message

Type a message after the footer and save. Reopen the image — it displays normally; only a hex view reveals the text.

Why it's invisible

Most image renderers halt at FF D9. Appended bytes ride along in the file but never get drawn, so the picture looks untouched.

HxD leaves a .bak

Editing in HxD creates a backup file with a .bak extension in the same folder — a tell an examiner can look for.

Task 2 — Extract a file hidden inside another

3 Find the embedded PNG in PlanC.jpg

Search PlanC.jpg for the PNG header 89 50 4E 47 0D 0A 1A 0A (found mid-file), note the offset, then the PNG footer 49 45 4E 44 AE 42 60 82 at the end.

4 Carve the hidden file out

Select block between the two offsets and Save selection as Exported picture.png. Open it — a complete second image was hiding inside the first.

📸 Screenshot for your report

The PNG you carved out of PlanC.jpg, open and rendering.

Any file type can hide here

The lab uses a PNG, but ZIP, DOCX, XLSX and others are commonly embedded. Recognizing their signatures (Lab 07) is what lets you find them.

Task 3 — Alternate Data Streams

5 Hide a file in an ADS

At the command prompt in E:\FOR_LAB_010\ADS\Exercise1:

C:\> type legitimate_program.exe > Legitimate_program.exe:secret.txt

creates a hidden stream. A normal dir won't show it; you open it with notepad legitimate_program.exe:secret.txt.

6 Detect it with dir /r

The detection move:

C:\> dir /r

reveals Legitimate_Program:secret.txt:$DATA — the :$DATA attribute marks an ADS. ADS exist only on NTFS and are a classic malware hiding spot.

Alternate Data Streams - Hiding a Message in a File's Data Stream There are many anti-forensic techniques out there. Hiding data within Alternate Data Streams (ADS) is another simple anti-forensic method that can be done with very little investment. ADSs are file attributes that are only found on NTFS file systems and are not visible using traditional methods. They are often used as a hiding place for malware and other potentially unwanted programs, which means they should be considered in forensic examinations. In this exercise, we will teach you how to hide a file within another file's data stream. We will also teach you the command to use to detect this data as well. All these commands will be done using the Windows command line so let us begin by opening it.

Reference — the two techniques

TechniqueHides data…Detect by
Append after footerAfter a file's end-of-file markerHex view past the footer (FF D9 for JPEG)
Embed a fileFull file inside anotherSearching for a second file's header/footer signatures
Alternate Data StreamIn an NTFS file's extra streamdir /r (shows :name:$DATA); file size vs. anchor
Why these matter

Both techniques carry no dates on the hidden payload and are easy to miss. An examiner who routinely checks past footers and runs dir /r catches data a casual review would walk right past.

Where people get stuck

SymptomCauseFix

Unexpected .bak filesHxD backs up on editNote them — they can reveal that a file was altered.

Why it matters in court

Absence of a finding isn't absence of evidence

Steganography and ADS are designed to make an examiner conclude 'nothing here.' Checking past footers and running dir /r are the habits that turn a missed case into a made one.

  • NTFS-only ADS — a reason to know the file system (Lab 05).
  • Signature knowledge (Lab 07) is what finds embedded files.
  • Chain-of-custody caution — never create these on real evidence; they alter integrity.

Course relevance

Core data-hiding content in Module 9 (Analysis and Validation). Know steganography basics, ADS, that ADS is NTFS-only, and the dir /r detection.

Check yourself

1. How can a message hide in a JPEG yet the image still display normally?

Image viewers stop reading at the JPEG footer FF D9; data appended after it is never rendered but still rides inside the file, visible only in a hex view.

2. Which command reveals an Alternate Data Stream, and what marks it in the output?

dir /r; the stream appears with the :name:$DATA attribute.

3. On which file system do Alternate Data Streams exist, and what happens if the host file leaves it?

NTFS only. The ADS is bound to its anchor file — delete/move the host (or move it off NTFS) and the stream is lost.

4. What lets you find a whole file embedded inside another file?

Searching for the embedded file's signature — its header and footer bytes — within the host, then carving between them.

Cheat sheet

Steganography

  • Data rides after FF D9 (JPEG EOF)
  • Detect: hex view past the footer
  • Embedded file = header+footer inside
  • HxD Select block → Save selection

ADS (NTFS only)

  • Create: type f > host:stream
  • Open: notepad host:stream
  • Detect: dir /r → :$DATA
  • Dies with the host file

01Overview — what this lab is really teaching

Not everyone wants their data found. Steganography hides information inside an innocent-looking file — a secret message or an entire second file tucked behind a photo's end-of-image marker, where normal viewers never look. Alternate Data Streams (ADS) hide data in a parallel 'fork' of an NTFS file that doesn't show up in Explorer or a plain dir. Both are anti-forensic techniques, and both are detectable if you know where to look.

You'll append a hidden message past a JPEG's FF D9 footer in HxD, extract a complete PNG that was concealed inside a JPEG, then create and — crucially — detect an ADS from the Windows command line with dir /r.

The reason to practice the hiding is to understand the detecting. Once you've seen that image viewers stop at the end-of-file marker and ignore everything after it, you know to always inspect past the footer. Once you've created an ADS and seen it vanish from dir but appear under dir /r as file:stream:$DATA, you'll never again trust a plain directory listing on an NTFS volume.

03Walkthrough

Task 1Hide a message past the JPEG footer

Viewers stop at FF D9, so anything after it is invisible to them but plain in hex.

  1. Open WhatsApp-Encryption.jpg in HxD. Search > Go to → end (backwards) → confirm the FF D9 footer.
  2. Click after the last byte in the text pane and type a message. HxD warns the file size will change — acknowledge and continue.
  3. Save. Reopen the image — it displays normally; the message is only visible in hex/text view because viewers ignore data past FF D9.
    📸Screenshot for your report: The appended message visible after FF D9 in HxD's text pane.

Task 2Extract a file hidden inside a file

A whole PNG can be appended behind a JPEG — find it by signature and carve it (Lab 7 skills).

  1. Open PlanC.jpg in HxD. Find the PNG header 89 50 4E 47 0D 0A 1A 0A → note offset (0x191F9).
  2. Find the PNG footer 49 45 4E 44 AE 42 60 82 → note the last byte's offset.
  3. Edit > Select block between the two offsets → File > Save selection → Exported picture.png. Open it — a complete image was hidden inside the JPEG.
    📸Screenshot for your report: The extracted PNG open, showing the hidden image.

Task 3Create and detect an ADS

ADS hides data in a named stream Explorer and plain dir never show.

  1. Open CMD, E:, then:
  2. Command Prompt
    cd FOR_LAB_010\ADS\Exercise1
  3. Hide a text stream inside a program:
  4. Command Prompt
    type legitimate_program.exe > Legitimate_program.exe:secret.txt
  5. Open and edit the hidden stream directly (it's invisible to a normal dir):
  6. Command Prompt
    notepad legitimate_program.exe:secret.txt
  7. Detect it — this is the forensic point:
  8. Command Prompt
    dir /r
  9. The listing now shows Legitimate_program.exe:secret.txt:$DATA with its own size and no timestamps — the ADS giveaway.
    📸Screenshot for your report: The dir /r output revealing the :secret.txt:$DATA stream.

04Reference — detecting hidden data

Steganography detection

  • Always inspect past the end-of-file marker. Data after FF D9 (JPEG), IEND (PNG), or %%EOF (PDF) is a red flag.
  • Compare file size to expected. An image far larger than its visible content suggests appended data.
  • Hash mismatch against known-good. If you have the original's hash (Lab 20), a changed hash on a 'system' file is suspicious.
  • Scan for nested signatures (Lab 7): a file signature inside another file means an embedded file.
  • Note: this lab covers appended steganography. True steganography that alters pixel/LSB data needs statistical tools (StegDetect, zsteg) — harder to spot.

ADS detection

  • dir /r reveals streams as filename:streamname:$DATA.
  • PowerShell: Get-Item file -Stream * lists all streams.
  • Streams have their own size but no independent timestamps; editing a stream updates the host file's modified time.
  • ADS only exists on NTFS. Copy the file to FAT/exFAT/a non-NTFS medium and the stream is silently dropped — which is both a detection trick and a reason to image, not copy.
  • Legitimate uses exist too (e.g. Zone.Identifier, the 'downloaded from the internet' mark), so a stream isn't automatically malicious.

07Making it defensible

Finding hidden data is impressive; proving it was deliberately hidden is the real work:

  • Document how you found it. The offset of appended data, the dir /r output, the extraction method — reproducibility matters doubly for anti-forensic findings.
  • Hash both host and hidden file (Lab 20). You'll need to prove the hidden content hasn't changed since recovery.
  • Distinguish deliberate from benign. A Zone.Identifier ADS is normal; a program carrying a hidden text file is not. Say which and why.
  • Image, never copy. Copying to non-NTFS destroys ADS — if you lose a stream in handling, you've destroyed evidence.
On the stand

Hidden data cuts toward intent — 'why conceal it unless you knew it was wrong?' But be precise: appended data could be accidental, and an ADS could be benign. Show the deliberate-concealment indicators rather than asserting intent.

09Check yourself

1. Why can a message hidden after a JPEG's FF D9 footer be invisible in an image viewer but obvious in a hex editor?

Image viewers stop parsing at the end-of-image marker (FF D9) and ignore everything after it, so appended data never renders. A hex editor shows the raw bytes, so the appended text is plainly visible.

2. What command reveals Alternate Data Streams, and what do they look like in the output?

dir /r. Streams appear as filename:streamname:$DATA, with their own size but no independent timestamps.

3. Why does copying an ADS file to a USB stick often destroy the hidden stream?

ADS is an NTFS feature. FAT/exFAT (common on USB) and most transfer paths (email, cloud) don't support streams, so the alternate stream is silently dropped. This is why you image evidence rather than copy it.

4. The lab hides appended data. What harder form of steganography does its signature-search method miss?

True pixel/LSB steganography, which alters the image data itself rather than appending after the footer. It leaves no nested file signature and requires statistical steganalysis tools to detect.

11Cheat sheet

  • Nested signature = embedded file (Lab 7)
  • Size bigger than content = suspicious
  • LSB/pixel stego needs steganalysis tools

  • Get-Item -Stream * (PowerShell)
  • Own size, no timestamps; Zone.Identifier is benign

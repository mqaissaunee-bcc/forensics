Overview — what this lab is really teaching

Deleted files don't vanish — their directory entry goes, but the data lingers in unallocated space until overwritten. Data carving recovers those files by their content alone, using file signatures (headers and footers) rather than the file system's metadata. You'll carve by hand in HxD, then let Autopsy automate it — and compare.

The reason to suffer through the manual version first: once you've highlighted header-to-footer yourself, you understand exactly what the automated carver is doing — and why it sometimes produces partial or misnamed files.

Tools & environment

WinOS for manual carving in HxD, then Autopsy's PhotoRec Carver ingest module for automation.

Footers can lie

A footer byte sequence can appear mid-file as a false positive. For PDF and JPEG, confirm you're at the real end by looking for the run of zeros out to the end of the sector.

Walkthrough

Task 1 — Carve by hand in HxD

1 Open the image, set decimal offsets

Tools > Open disk image → Lab007.001 (sector 512). Set Offset base = Decimal so the offsets match the instructions.

2 Carve the XLSX

Find (Hex-values) the header 50 4B 03 04 14 00 06 00 → note the start offset. Find the footer 50 4B 05 06, then add 18 bytes for the end offset. Edit > Select block (Ctrl+E) with both offsets, then File > Save selection as Carved.xlsx. It should open cleanly (~14 KB).

Delete the spaces in the offset boxes

Select block rejects trailing spaces behind the start/end offset values — clear them before OK.

3 Carve the PDF (mind the false footer)

Find 25 50 44 46 (search All — the PDF is before the XLSX). Find the footer 0D 0A 25 25 45 4F 46 0D 0A; the first hit may be a false positive (blanks, not zeros, follow). Search again for the real end, Select block, save Carved.pdf.

4 Carve the JPEG

Find header FF D8 FF E0, then footer FF D9 — again watching for a false positive before the true end (look for zeros to the sector boundary). Select block, save Carved.jpg.

Task 2 — Automate with Autopsy

5 Run the PhotoRec Carver

New case, add NDG Lab7.001, Deselect All ingest modules, enable PhotoRec Carver, Finish. It carves everything it can from unallocated space.

6 Review carved files & expand archives

Under the NTFS/exFAT volume, open $CarvedFiles (13 files here). Names won't match the originals — PhotoRec names by cluster/block. Then run the Embedded File Extractor module to expand ZIP/RAR/7z and Office files so their contents are added to the case.

Why names change

Carving recovers content, not the file-system metadata, so the original filename is usually gone. The carver invents a name from the block number (or embedded metadata, if present).

Why it matters in court

Recovered ≠ attributed

Carving proves a file's data existed in unallocated space — it does not, by itself, tell you who put it there or when. Pair carved content with link files, registry MRUs, and timeline data (Labs 04, 08, 14) to build attribution.

  • Deleted isn't gone. The central fact that makes recovery possible.
  • Explain the method. Being able to describe signatures and carving demystifies the automated tool for a jury.
  • Note the limits. Partial carves and lost names are inherent; disclose them.

Course relevance

Part of Module 9 and foundational to file recovery generally. Know the three signatures above, header/footer carving, unallocated space, and the manual-vs-automated trade-off.

Check yourself

1. What makes it possible to recover a deleted file by carving?

Deleting a file removes its directory/metadata entry but leaves the data in unallocated space until it's overwritten; carving finds that data by its signature.

2. Your JPEG carve stops at the first FF D9 but the image is broken. What likely happened?

The first FF D9 was a false positive inside the file. Continue to the true footer — the one followed by zeros out to the sector boundary.

3. Why don't carved files keep their original names?

Carving recovers content from unallocated space without the file-system metadata, so the carver names files by block number (or embedded metadata) rather than the lost original name.

4. What's the value of carving by hand before using PhotoRec?

It teaches exactly what the automated carver does — signature matching and length determination — so you can explain and trust (and debug) the automated results.

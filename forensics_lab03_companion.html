01Overview — what this lab is really teaching

Sometimes you can't pull the plug. The machine is running full-disk encryption whose key lives only in RAM, it's a server you can't take offline, or you need fast triage to decide whether a deeper exam is even warranted. Live forensics is the art of pulling useful evidence from a running system while disturbing it as little as possible.

You'll work entirely from the DART toolkit inside DEFT 8 — a portable live-response suite — using Drive Manager for disk serials, FTK Imager Lite to map user directories, TreeSizeFree to find big/hidden caches of data by size, WinAudit for a full system inventory, and BrowsingHistoryView to grab web history on the spot.

The through-line: run your tools from external media, write your output to external media, and log everything. DART keeps its own action log for exactly this reason. Every tool you run leaves a trace on the subject system; your job is to keep that footprint small, known, and documented.

03Walkthrough

Task 1Open DART and set its log path

DART logs every action — this log is part of your documentation and must live on external media.

  1. Browse to Desktop\Toolbox\deft-8.2-002 and run dart.exe. Read and accept the DART DISCLAIMER.
  2. When prompted, point DART's log at E:\FOR_LAB_003\DART_LOGS — never the computer under examination.
  3. Note DART's categories: Acquire, Data Recovery, Forensics, Incident Resp., Networking, Password, Visualize, Utility.

Task 2Pull disk identity with Drive Manager

Serial numbers tie the physical device to your case documentation.

  1. Incident Resp. → System Info → DriveMan → Start as Admin.
  2. Select (C:) → Disk Info: record hard-drive serial, volume serial, total size, allocated/unallocated clusters, physical name, fixed/removable.
    📸Screenshot for your report: The Disk Info window with the C: serial numbers.

Task 3Map user directories with FTK Imager Lite

Live users' files are the richest evidence; know where they live.

  1. Acquire → Image → FTK Imager → Start as Admin.
  2. File > Add Evidence Item > Physical Drive > PHYSICALDRIVE0, expand to the largest partition → NONAME [NTFS] → root → Users → Administrator.
  3. Note that FTK shows hidden/system folders (e.g. AppData) that Windows Explorer hides — a live-triage advantage.

Task 4Find data by size with TreeSizeFree

Big files hide in plain sight; sorting by size surfaces downloaded media and caches fast.

  1. Incident Resp. → System Info → TreeSizeFree → Start as Admin.
  2. Scan Local Disk (C:), expand Users > Administrator, and check Downloads for any large video file. Note its name.

Task 5Inventory the system with WinAudit

A full system snapshot (OS, installed software, install dates) in one report.

  1. Incident Resp. → System Info → WinAudit → Start as Admin → Audit.
  2. Review System Overview and Installed Software (Active Setup vs user-installed Programs, with install dates).
  3. Save as a Web Page (HTML, include images) to E:\FOR_LAB_003\FOR_LAB_003_Audit.
    📸Screenshot for your report: The WinAudit report with Installed Software showing install dates.

Task 6Capture web history with BrowsingHistoryView

Often the single most telling live artifact — where the user went and when.

  1. Forensics → Browser → BrowsingHistoryView 64-bit → Start as Admin → OK (default options).
  2. Review URL, title, visit time, visit count, 'visited from', browser, and user columns.
  3. Edit > Select All, File > Save Selected Items → HTML - Vertical to E:\FOR_LAB_003.

04Reference — when to go live, and DART's toolset

When live forensics is the right call

  • Full-disk encryption whose key is only in RAM — power off and the disk is unreadable.
  • Can't take it offline — production servers, critical infrastructure.
  • Triage — decide fast whether a full exam is justified.
  • Volatile-only evidence — network connections, running malware, open handles (see Lab 2).

06Manual corrections & currency notes

The NDG manual was written in 2020–21. These are the places where it is wrong, inconsistent, or out of date — worth knowing before you trust a screenshot.

WhereThe manual saysWhat's actually true
DEFT / DARTBuilt around DEFT 8 and DART 2.0DEFT is discontinued (last release ~2018). The current live Linux forensic distro is CAINE (also in this pod). The concepts — run from external media, log everything, write out externally — are what transfer, not the specific suite.
BrowsingHistoryView / NirSoft toolsUsed as live browser-history toolsStill maintained and widely used, but many AV engines flag NirSoft utilities — expect to document that.
WinAuditUsed for system inventoryStill functional but effectively unmaintained; modern live-triage often uses KAPE, CyLR, or velociraptor to collect artifacts for offline parsing.
'Live analysis won't alter much'Implied by the lab's gentle framingEvery live tool alters the system — access times, prefetch, memory. Live forensics is a documented trade-off, not a zero-impact method.

07Making it defensible

Live work is inherently invasive, so defensibility rests on discipline:

  • Tools from external media, output to external media. Never install on, or write to, the subject system.
  • Keep DART's log. It's a contemporaneous record of exactly what you ran — store it on E:, treat it as evidence.
  • Record disk serials up front. They link this running machine to your chain-of-custody paperwork (Lab 21).
  • Account for AV changes. If you disabled antivirus, say so, when, and why.
On the stand

'You ran software on a running machine — how do we know you didn't plant or alter evidence?' Your answer is the DART action log plus your own contemporaneous notes, both stored off the subject system.

09Check yourself

1. Name two situations where live forensics beats pulling the plug.

Full-disk encryption whose key lives only in RAM (powering off makes the disk unreadable), and a system that can't be taken offline such as a production server. Fast triage and volatile-only evidence are two more.

2. Where must DART's log and all your output go, and why?

On external media (E:), never the computer under examination. Writing to the subject drive overwrites unallocated space and alters the evidence; the external log is your defensible record of what you did.

3. Why does FTK Imager Lite show folders Windows Explorer doesn't?

It reads the file system directly and displays hidden and system folders (like AppData) and even deleted entries, which Explorer suppresses — useful for finding user artifacts during live triage.

4. Your AV quarantines a live-response tool. What's the correct response?

Document it, and in a sanctioned engagement disable AV and record that you did so and why. Never silently bypass controls — the goal is a defensible, documented process.

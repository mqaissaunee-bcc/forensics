Overview — what this lab is really teaching

Sometimes you can't pull the plug and image a drive — the system must stay running, or it's encrypted and shutting down loses access. Live forensics is the art of collecting evidence from a powered-on machine while leaving the smallest possible footprint and documenting every step.

The core tension here is identical to Lab 02's: acting on a live system changes it. The skill is choosing lightweight tools, running them from external media, writing output to an external drive, and taking meticulous notes so every change you cause is accounted for.

Walkthrough

1 Open DART and set the log path

From Desktop > Toolbox > deft-8.2-002, run dart.exe, accept the disclaimer, and point its log to E:\FOR_LAB_003\DART_LOGS.

2 Document the drive with DriveMan

Incident Resp. > System Info > DriveMan > Start as Admin. Select C: and open Disk Info to read the physical and volume serial numbers, total size, and allocated/unallocated clusters — all needed for chain-of-custody documentation.

3 Identify user directories with FTK Imager Lite

Acquire > Image > FTK Imager. Add PHYSICALDRIVE0, find the main data partition (the largest one), expand root > Users > Administrator. FTK Imager shows hidden folders like AppData that Windows Explorer conceals — a reminder to look where the user can't.

4 Triage by size with TreeSizeFree

Scan > Local Disk (C:), then drill into Users > Administrator. Large files cluster where interesting data hides; note any video file in the Downloads folder.

5 Inventory the system with WinAudit

Run the audit, review System Overview and Installed Software (it even separates default OS components from user-installed programs with install dates), then Save as an HTML report to E:\FOR_LAB_003\FOR_LAB_003_Audit.

Forensics > Browser > BrowsingHistoryView. It aggregates history across browsers with URL, title, visit time, visit count, browser, and user. Edit > Select All, then File > Save Selected Items as HTML to the evidence drive.

Why it matters in court

Notes are the evidence of your process

On a live system you can't claim "nothing changed." What you can show is a complete, timestamped record of every tool you ran and every action you took — which is why DART logs and your own notes carry real weight.

  • Minimize and disclose. Smallest footprint, fully documented.
  • Keep output off the subject. Exports and logs on external media only.
  • Serial numbers tie the evidence to the device. DriveMan's physical serial is chain-of-custody gold.

Course relevance

Supports Module 10 (live acquisitions) and Module 3 (acquisition strategy). Know when live beats dead, the footprint trade-off, and the discipline of documenting a running system.

Check yourself

1. Give two situations where live acquisition is the right call over imaging a powered-off disk.

Any two: the system can't be shut down (critical service), the disk is encrypted and powering off loses access, you need volatile data like RAM or network connections, or you're doing fast triage.

2. Why store DART logs and exports on the E: drive rather than the C: drive being examined?

Writing to the subject's drive creates more artifacts and risks overwriting evidence. External media keeps your activity off the evidence and preserves it.

3. Why use FTK Imager to browse the file system instead of Windows Explorer?

FTK Imager reveals hidden and system files and folders (like AppData) and deleted entries that Explorer conceals from a normal user view.

4. You can't guarantee a live system is unchanged. What makes your live acquisition defensible anyway?

A minimal footprint using lightweight tools plus a complete, timestamped record (DART logs and your notes) of exactly what you ran and when.

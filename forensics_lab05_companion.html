Overview — what this lab is really teaching

Before you trust what a tool tells you a volume is, you should be able to read it yourself. This lab drops to the byte level with a hex editor and manually parses the structures that define a disk: the Master Boot Record (MBR) partition table and each file system's Volume Boot Record (VBR).

You'll identify FAT, NTFS, and exFAT by their on-disk signatures and decode their serial numbers, sizes, and cluster geometry. The deeper point: file systems store multi-byte values in little-endian (reversed) order, and knowing where each field lives lets you spot volumes that have been hidden or manipulated.

Walkthrough

Task 1 — Read the partition table (MBR)

1 Open the FAT image and go to offset 446

Tools > Open disk image → NDG FAT Lab5.001, sector size 512. Switch Offset base to Decimal, then Go to 446 and highlight the next 16 bytes — the first partition entry.

2 Decode the 16-byte partition entry

Break the entry into its fields. The 5th byte is the file-system type:

BytesFieldFAT example
1Boot flag80 = active / bootable
2–4Starting CHS—
5File-system type0E = FAT (07 = NTFS/exFAT)
6–8Ending CHS—
9–12Start sector (LBA)3F 00 00 00 → 63
13–16Sector count86 39 01 00 → 80262 → ×512 ≈ 40 MB
The VBR is at the start sector

Start sector 63 × 512 bytes = offset 32256 — that's where the volume's boot record (and all the file-system fields) begin.

Task 2 — Identify the file system (VBR)

3 FAT fields at sector 63

Go to 32256 and read: OEM ID (MSDOS5.0), bytes/sector (00 02 = 512), sectors/cluster, media type (F8 = fixed/removable), total sectors, volume serial number, and file-system type (FAT16).

📸 Screenshot for your report

The FAT VBR at offset 32256 with the OEM ID (MSDOS5.0) and FAT16 type highlighted.

4 NTFS — the tell-tale differences

Open NDG NTFS Lab5.001. The partition entry's type byte is now 07, OEM ID reads NTFS, and uniquely you can read the MFT start cluster (offset 48 in the VBR). The volume serial sits at a different offset than FAT.

5 exFAT — the modern one

Open NDG exFAT Lab5.001. Type byte is also 07, but OEM ID reads EXFAT and the next 53 bytes are zero. exFAT stores sizes as powers of two — bytes/sector is 2^N (e.g. 09 → 2⁹ = 512), sectors/cluster likewise.

MBR has a hard limit

The 64-byte partition table holds only four 16-byte entries — hence max four primary partitions (or three primary + one extended). GPT replaces MBR on modern large disks, but MBR parsing is still bread-and-butter.

Why it matters in court

Reading raw bytes defeats hiding

Technical users manipulate partition tables and VBRs to conceal volumes. An examiner who can parse the MBR/VBR by hand can prove a volume exists, identify its real file system regardless of a faked extension, and extract its serial for attribution.

  • Ground truth over tool output. You can verify, not just trust, what a suite reports.
  • Volume serials link a volume to link-file and registry artifacts (Labs 04, 08).
  • Detect manipulation — mismatched type bytes vs. OEM IDs are a red flag.

Course relevance

Underpins Module 5 (Windows/CLI file systems) and feeds Module 7 (Linux/Mac file systems). Know MBR layout, the FAT/NTFS/exFAT signatures, little-endian, and how to compute a VBR offset from a start sector.

Check yourself

1. The on-disk bytes for a sector count are 86 39 01 00. What's the decimal value and why?

80262. The value is little-endian, so reverse to 00 01 39 86 before converting.

2. A partition entry's 5th byte is 07 and the OEM ID reads EXFAT. What file system is it?

exFAT. Type byte 07 is shared by NTFS and exFAT, so the OEM ID string disambiguates them.

3. The start sector is 63. At what byte offset does the VBR begin, and how did you get it?

32256 — start sector 63 × 512 bytes per sector.

4. Why can an MBR disk have at most four primary partitions?

The partition table is 64 bytes and each entry is 16 bytes, so only four entries fit.

Cheat sheet

MBR

  • Partition entries @ offset 446
  • Each entry = 16 bytes, max 4
  • Byte 5 = FS type (0E FAT · 07 NTFS/exFAT)
  • Signature 55 AA @ 510
  • VBR offset = start sector × 512

VBR / identify

  • OEM ID: MSDOS5.0 · NTFS · EXFAT
  • All multi-byte = little-endian
  • exFAT sizes = 2^N
  • NTFS: MFT start @ offset 48
  • Volume serial for attribution

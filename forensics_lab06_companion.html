01Overview — what this lab is really teaching

A modern drive holds millions of files. You cannot open them all. Keyword search is how you find the needle — but a sloppy keyword returns ten thousand hits and buries the one that matters, while a good keyword returns exactly the file you need. This lab is about the difference.

You'll build a case in Autopsy, run its Keyword Search ingest module against a forensic image, and compare the three search types — Exact Match, Substring Match, and Regular Expression — watching how each one trades precision for reach. You'll also see the difference between an indexed search (fast, because the text was catalogued during ingest) and the way vague terms like hack drown you in false positives while a precise term like hackersteam lands one clean hit.

The skill being built is keyword discipline: starting from the artifacts you already have (an email address, a serial number, a username, a handle) rather than from guesses, and escalating from exact to substring to regex only as needed. Case creation itself matters too — Autopsy's case structure is what keeps evidence from cross-contaminating and what lets you generate a defensible report.

03Walkthrough

Task 1Create the case

A case keeps evidence, tags, bookmarks, and reports isolated — the basis of a defensible exam.

  1. Open Autopsy → New Case → name it FOR_LAB_006_KWS → Next, fill examiner info (your name) → Finish.
  2. Add Data Source → Disk Image or VM file → browse to FOR_LAB_006.E01.
  3. Tip

    Set the time zone to the evidence's time zone if known; otherwise your local zone. Every timestamp Autopsy shows depends on this.

Task 2Configure the keyword search module

Only the Keyword Search module is needed here; build a custom list.

  1. At Configure Ingest Modules, tick Keyword Search and uncheck the default lists on the right.
  2. Global Settings → Lists → New List FOR_LAB_006_Keywords.
  3. Add exact-match keywords (one per line): Lookatlan, 0010a4933e09, yahoo, hackersteam.
  4. Add hack as a Substring Match, and hack* as a Regular Expression. OK through to Finish.

Task 3Watch the ingest and read results

Hits populate live as Autopsy indexes.

  1. Ingest runs; results fill the Keyword Hits tree. Due to time, you can cancel above ~30% — enough to see the pattern.
    📸Screenshot for your report: The Keyword Hits tree with your custom list expanded.
  2. Compare: Exact lookatlan finds only that literal string (misses variants like look@lan); Substring hack returns 1000+ noisy hits; Regex hack* matches patterns.

Task 4See precision vs recall for real

The core lesson, made concrete.

  1. Note that hack buries hackersteam among thousands of results, while the exact term hackersteam returns one hit in channels.txt.
    📸Screenshot for your report: The single exact-match hit for hackersteam inside channels.txt.
  2. Run an Index Search (Keyword Search dropdown) with regex hackerst.* — now you also catch hackerstone and friends. Precision down, recall up.
  3. Try a few of the extra terms in keywords.txt to feel how term quality drives result quality.

04Reference — search types and when to use them

TypeMatchesPrecision / RecallUse when
ExactThe literal string onlyHigh precision, low recallYou know the exact term (an address, serial, handle).
SubstringAny string containing your termLow precision, high recallYou know a fragment and can tolerate noise.
RegexA patternTunableStructured data: emails, phone numbers, card numbers, GUIDs.

Keyword discipline

  • Start from artifacts, not guesses. Real usernames, email addresses, serial numbers, and handles make sharp keywords. 'drugs' does not.
  • Escalate, don't lead with, substring/regex. Exact first; widen only when you miss.
  • Case-insensitive by default here — Hack and hack match the same.
  • Useful regex: . = any char, * = zero-or-more of the preceding, \d = a digit. \d{3}-\d{4} finds phone fragments.
  • Save your search results so they populate the tree — otherwise you'll re-run them.

05Where people get stuck

Most problems in this lab fall into one of these.

SymptomLikely causeFix
Thousands of hits, can't find the real oneKeyword too vague (substring on a common word)Narrow to an exact, specific term. 'hackersteam' not 'hack'.
Exact search misses an obvious variantSpecial characters or spacing differExact means literal — look@lan won't match lookatlan. Use substring or regex for variants.
Ingest is slowFull-text indexing of the whole imageExpected. You can cancel above ~30% for this exercise; a real exam lets it finish.
Regex search returns nothingPattern syntax errorCheck metacharacters: * needs a preceding character; test a simpler pattern first.
Results vanished after searching'Save search results' was unchecked on an index searchRe-run with Save enabled so hits persist in the tree.

07Making it defensible

Search is where bias creeps in — you tend to find what you search for — so method matters:

  • Document your keyword list. What you searched (and why) is as important as what you found. Save the list with the case.
  • Record the search type per term. An exact hit and a substring hit mean different things evidentially.
  • Verify every hit in context. A keyword match is a pointer, not a conclusion — open the file and confirm the term means what you think.
  • Keep the case structure intact. Autopsy's case is what prevents cross-contamination and backs your report.
On the stand

Defense counsel will ask whether you went looking only for inculpatory terms. A documented, artifact-driven keyword list — not a fishing expedition — is your answer.

09Check yourself

1. Why does a substring search for 'hack' make 'hackersteam' hard to find?

Substring matching returns every string containing 'hack' — thousands of hits — and the one relevant file is buried among them. An exact search for 'hackersteam' returns a single, clean hit.

2. Give one artifact that makes a good keyword and explain why.

An email address, serial number, or unique username — they're specific and tied to the subject, so they return few, highly relevant hits rather than generic noise. (A word like 'drugs' is the opposite.)

3. What's the difference between an exact search and a regex search, evidentially?

Exact confirms a literal string is present — strong, narrow. Regex matches a pattern, so it finds variants and structured data (emails, numbers) but needs each hit verified in context before it means anything.

4. Why document your keyword list with the case?

It shows what you searched and why, demonstrating an artifact-driven method rather than a biased fishing expedition — which is exactly what the defense will probe.

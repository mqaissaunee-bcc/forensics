Overview — what this lab is really teaching

A full disk can hold millions of files. Keyword searching is how you find the handful that matter without reading everything. This lab uses Autopsy (built on The Sleuth Kit) to index an evidence image and run three kinds of search — and, just as important, to learn why a vague keyword buries you and a refined one pinpoints the evidence.

Tools & environment

On CSI-Linux, Autopsy 4 drives everything. Work happens inside a case (which keeps evidence, tags, and reports organized and prevents cross-contamination). The Keyword Search ingest module indexes the image as it processes it.

Search typeMatchesUse when

Substring MatchAny string containing your termYou want variants of a root (e.g. hack).

Walkthrough

1 Create the case and add the image

Autopsy > New Case (FOR_LAB_006_KWS), fill the examiner info, add FOR_LAB_006.E01 as a Disk Image data source.

2 Enable only the Keyword Search module

At Configure Ingest Modules, enable Keyword Search and uncheck the default keyword lists so only your list runs.

3 Build a keyword list

Under Global Settings > Lists > New List (FOR_LAB_006_Keywords), add exact terms (Lookatlan, 0010a4933e09, yahoo, hackersteam), a substring term (hack), and a regex (hack*).

What * means here

In this regex the * matches the preceding character zero or more times. The index search later uses hackerst.* — .* matches any characters, which is the more common regex idiom.

4 Run it and watch the hits populate

Let the ingest run; cancel after ~30% to save time (you'll see partial counts). Hits appear under Keyword Hits. Compare: exact matched only lookatlan (not look@lan); substring hack flooded with 1000+; hackersteam returned a single precise hit in channels.txt.

5 Use Index Search for ad-hoc queries

The ingest built a text index of the whole image. Use the Keyword Search box for new queries without re-ingesting — e.g. the regex hackerst.* finds hackersteam, hackerstone, and anything else starting with those letters. There's a keywords.txt in the evidence folder with more terms to try.

Reference — writing good keywords

PrincipleWhy
Be specificVague roots bury the one hit that matters under false positives.
Know the search typeExact misses variants; substring over-matches; regex is powerful but can over-reach.
Watch special charactersExact won't find look@lan when you searched lookatlan.
Index search is re-usableIngest indexes once; you can query repeatedly without re-processing.
Validate the hit in contextClick a hit to see it inside the file — a match isn't automatically relevant.

Why it matters in court

Search strategy is defensible methodology

How you searched — the terms, the types, what you excluded — is part of your documented method. A reproducible, well-reasoned keyword strategy stands up; a scattershot one invites challenge.

  • Reproducibility. Same case + same keyword list = same hits for a reviewer.
  • Relevance. You validate each hit in context rather than asserting a raw count.
  • Completeness. Indexing the whole image means you can answer new questions later without re-acquiring.

Course relevance

Supports analysis across Module 9 (Analysis and Validation). Know the three search types, when each applies, and why refined keywords beat broad ones.

Check yourself

1. You search Exact Match for lookatlan but the file contains look@lan. Why no hit, and what fixes it?

Exact Match requires the precise string; the @ breaks it. A substring or regular-expression search would catch the variant.

2. Why does the index search let you run new queries without re-processing the image?

The Keyword Search ingest already built a text index of all readable content, so later searches query the index instead of re-scanning the image.

3. Searching hack returns 1000+ hits; hackersteam returns one. What's the lesson?

Specific keywords cut noise; a vague root produces mostly false positives that waste analysis time.

4. A keyword hit isn't automatically evidence. What must you do with each one?

Open it and validate the match in context within the file to judge whether it's actually relevant.

Overview — what this lab is really teaching

Logs are the closest thing a computer keeps to a diary. This lab reads two of the most detailed Windows logs: the USN Journal (an NTFS change log of file creations, deletions, renames) and the Windows Event Logs (logons, password resets, updates, and much more, each with an Event ID).

The skill is knowing which log and which ID answers a given question, and using the parsed output to pin an action to a time — material that feeds straight into timeline analysis (Lab 14).

Walkthrough

Task 1 — Locate the logs

1 Find the USN Journal and Event Logs

Open the pre-processed case. The USN Journal lives in $Extend as $UsnJrnl:$J (the big change stream) and :$Max. Event logs live in Windows\System32\WinEVT\Logs as .evtx (Application/System/Security). Knowing the source matters even though the data's already parsed.

Task 2 — Read Event Logs by ID

2 Sort and find logon/logoff

Under Results > Extracted Content > Windows Event Logs, sort by Event Identifier then (Shift-click) Event Time. Find 4624 (logon) — the Event Detail shows the account, source computer, and logon type (2 = network/automated here). Then 4634 (logoff). A near-instant logon/logoff pair often indicates automated setup activity.

Type-to-find in the ID column

Click in the Event Identifier column and type the ID (e.g. 4624) to jump straight to those events.

3 Password resets and updates

4724 shows a password-reset attempt (affected user, computer, SID). 44 is an update download (e.g. a Defender definition — handy to prove AV currency at a time); compare with 43 (install) and 19 (install result) to see whether an update actually applied.

An Event Log detail — e.g. the 4624 logon showing the account and logon type.

Task 3 — Read the USN Journal

4 Interpret change types

Under NTFS UsnJrnl Entries, the Change_Type column is the key: file_created; file_closed, file_deleted; file_closed, data_appended; file_created; file_closed, file_new_name/file_old_name (renames). The MFT and Parent-MFT references tie each change to a specific file and folder.

5 Track a rename to a recycle-bin name

Search the Filename column (type $I / $R / Temp). You'll see a $I… index created, then a folder renamed Temp → $R… — the recycle-bin deletion pattern (cross-reference Lab 09), reconstructed purely from the change log.

Why it matters in court

Logs timestamp actions to users

Event Logs attribute logons and password changes to accounts; the USN Journal timestamps file creations, deletions, and renames. Together they answer 'who did what, when' — and feed the timeline that tells the story.

  • Attribution + timing from Event IDs.
  • File-change history from the USN Journal, even for deleted items.
  • Corroboration — USN renames confirm recycle-bin findings (Lab 09).

Course relevance

Part of Module 5/9. Know the key Event IDs (4624/4634/4724/44), logon types, the USN Journal's location and change types, and how both feed timeline analysis.

Check yourself

1. Which Event IDs record a successful logon and a logoff?

4624 for a successful logon and 4634 for a logoff.

2. In the USN Journal, which column tells you whether a file was created, deleted, or renamed?

The Change_Type column (e.g. file_created, file_deleted, file_new_name/file_old_name).

3. A 4624 event shows logon type 2 versus type 3. What's the difference?

Logon type 2 is an interactive/console logon; type 3 is a network logon. The type reveals how the user authenticated.

4. How can the USN Journal corroborate a recycle-bin finding?

It records the create of the $I index and the rename of a folder/file to a $R-style name — the exact deletion pattern seen in the recycle bin (Lab 09), reconstructed from the change log.

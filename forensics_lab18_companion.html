Overview — what this lab is really teaching

RAM is volatile — but Windows spills some of it to disk. The page file (pagefile.sys) is a backing store for memory, and it persists after shutdown, so it can hold fragments of what was in RAM: email addresses, URLs, even images the user viewed but never saved. This lab extracts pagefile.sys and mines it with Bulk Extractor Viewer.

Think of it as a second, disk-based shot at memory evidence — one you can get from a powered-off machine, unlike a live RAM capture (Lab 02).

Tools & environment

CSI-Linux: Autopsy to export pagefile.sys, Bulk Extractor Viewer to parse it into categorized reports, and the File Manager to view carved JPEGs.

Walkthrough

1 Export pagefile.sys

New case (FOR_LAB_018), add Lab18.E01, no ingest module. In vol2 find pagefile.sys in the root — here ~578 MB, which means ~578 MB of potential memory fragments. Extract File(s) to …/Export/Pagefile.

It's a system-protected hidden file

pagefile.sys sits in the root but is hidden and protected. A user can set it to clear on shutdown, but that's off by default — so it usually survives.

2 Run Bulk Extractor

Open Bulk Extractor Viewer, Tools > Run bulk_extractor, set Directory of Files to the Pagefile folder and an output folder, Submit Run. It carves and categorizes automatically.

3 Mine the email and URL histograms

Open email_histogram.txt — the top entry (e.g. hotdog918@hotmail.com) is the most-referenced address. Click an occurrence to see it in context in the page file; nearby you may find a LoginTime, country, ClientIP and port — a reconstructed user-profile fragment. Then review url_histogram.txt for visited sites.

Expect false positives

Automated carvers flag patterns, not verified facts. Always confirm a hit by reviewing it in context before relying on it.

4 View carved images

Use the File Manager to open Bulk extractor report\jpeg_carved\000. These are small, often partial images — a window into what the user saw, even if nothing was downloaded.

Why it matters in court

A second chance at volatile evidence

When you couldn't capture live RAM, the page file can still surface the email the suspect used, the sites they hit, and images they viewed — recovered from a powered-off disk. Validate each fragment, and present it as the partial evidence it is.

  • Memory evidence post-mortem — no live capture required.
  • Frequency = significance via histograms.
  • Honesty about fragments — partial, verify-in-context.

Course relevance

Supports Module 9/10. Know what the page file is, that it persists, how Bulk Extractor categorizes findings, and the discipline of validating carved hits.

Check yourself

1. Why can the page file yield memory-style evidence from a computer that's already powered off?

pagefile.sys is a disk-based backing store for RAM; data written to it persists after shutdown (it isn't cleared by default), so memory fragments survive.

2. In Bulk Extractor's email histogram, why pay attention to frequency?

The most-referenced address is likely the one the user actually used, distinguishing real activity from one-off hits an application happened to generate.

3. A carved JPEG from the page file is only half an image. Is that a failure?

No — the page file stores fragments, so partial images are expected and still show what the user viewed.

4. You find an email address in the output. What must you do before relying on it?

Review it in context in the page file (and corroborate) — automated carvers produce false positives.

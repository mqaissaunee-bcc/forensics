Overview — what this lab is really teaching

Browsers keep meticulous records: every URL visited, searches typed, downloads, cookies, and cached copies of pages. This lab finds and reads those artifacts for Chrome, Firefox, and Internet Explorer — each storing its data in a different place and format — and shows how Autopsy's Recent Activity module aggregates them.

The habit it builds: know where each browser hides its history, cookies, and cache, so you can verify the automated parser against the raw source.

Walkthrough

1 Create the case with Recent Activity

New case, add Lab13.E01, enable only the Recent Activity ingest module.

2 Chrome — read the SQLite tables

Navigate to Chrome's Default folder and open the History database. Key tables: urls (url, title, visit_count, last_visit_time), visits (visit_time in Chrome time, from_visit for redirects, visit_duration), keyword_search_terms, and downloads. The Cookies database's cookies table proves a site was visited and when. The Cache folder holds downloaded page content — switch to Thumbnail view to see images the user saw.

Browser time formats differ

Chrome stores timestamps in Chrome/WebKit time (microseconds since 1601); others use Unix time. Autopsy's parsed views convert them, but the raw database values need a converter like DCode.

3 Firefox — different files, same idea

History/cookies in *.default-release: places.sqlite (tables moz_origins, moz_places, moz_historyvisits — note visit_type indices for how a page was reached) and cookies.sqlite (moz_cookies). Cache sits under Local\…\cache2\entries.

4 Internet Explorer — the ESE database

IE's history is the ESE database WebCacheV01.dat in the WebCache folder (already parsed by Recent Activity). Cookies live in INetCookies (and Low) as separate files; cache in INetCache\IE (with real file extensions). Thumbnail view again reveals cached images.

5 Review the aggregated results

Results > Extracted Content > Web History gives a single, time-parsed list across all browsers. This is why you learned the manual locations first — so you can cross-verify the aggregate.

Reference — what browser artifacts prove

ArtifactEstablishes
History (urls/moz_places)Which sites were visited, when, how often
Search termsWhat the user searched for
DownloadsWhat files were pulled down, from where, and their size
CookiesThat a site was actually visited (and sometimes session details)
CacheThe actual content/images the user saw — even if now offline
visit_type / from_visitHow a page was reached (typed, link, bookmark, redirect)

Why it matters in court

Verify the parser against the source

Automated aggregation is convenient, but knowing where each artifact physically lives lets you cross-verify a tool's output — which is exactly the kind of methodology that survives cross-examination.

  • Intent and knowledge often come from searches and visited URLs.
  • Cache shows what was seen, not just what was requested.
  • Cross-verification (manual location vs parsed result) is defensible practice.

Course relevance

Core to Module 9 and web investigations generally. Know each browser's storage locations and formats (SQLite vs ESE), the key tables, and the browser time formats.

Check yourself

1. Chrome, Firefox, and IE all store history — what's the key format difference for IE?

Chrome and Firefox use SQLite databases; Internet Explorer uses an ESE database (WebCacheV01.dat).

2. Beyond proving a site was requested, what can the browser cache show?

The actual content and images the user saw — cached copies that can be viewed even when the page is now offline.

3. A Chrome timestamp is a huge number that doesn't look like a normal date. Why, and how do you handle it?

Chrome stores times in WebKit/Chrome time (microseconds since 1601). Use Autopsy's parsed view or convert with a tool like DCode.

4. Why learn the manual storage locations if Autopsy aggregates everything for you?

So you can cross-verify the automated output against the raw source — defensible methodology that holds up under scrutiny.

Cheat sheet

Where it lives

  • Chrome: User Data\Default (SQLite)
  • Firefox: *.default-release (SQLite)
  • IE: WebCacheV01.dat (ESE)
  • Cache folders hold seen content

Read it

  • urls / moz_places = history
  • keyword_search_terms = searches
  • cookies = visited + session
  • Thumbnail tab = cached images
  • Results → Web History = aggregate

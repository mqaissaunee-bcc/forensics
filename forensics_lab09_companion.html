01Overview — what this lab is really teaching

Deleting a file to the Recycle Bin doesn't destroy it — it moves and renames it, and Windows keeps an index recording what it was, where it came from, how big it was, and exactly when it was deleted. Better still, the Recycle Bin is organized per user by SID, so a deleted file can be tied to a specific account. This lab reads both the old and new Recycle Bin formats.

You'll use Autopsy to find the Recycle Bin on two images — the legacy RECYCLER (Windows XP and earlier) and the modern $Recycle.bin (Vista+) — then export the index files and parse them with Rifiuti and Rifiuti-Vista on the command line to recover the deletion metadata.

The two formats encode the same facts differently. RECYCLER / INFO2: deleted files are renamed D<drive><seq>.ext (so Dc1.exe = first file deleted from C:), and a single INFO2 index holds all the original paths, drives, sizes, and deletion times. $Recycle.bin: each deletion makes a $R… file (the data) and a matching $I… file (the metadata index). Reading the SID folder name is what attributes the deletion to a user — and because SIDs are never reused, gaps in the RID range reveal deleted accounts too.

03Walkthrough

Task 1Parse the legacy RECYCLER (INFO2)

Windows XP and earlier: one INFO2 index for the whole bin, files renamed by drive+sequence.

  1. Autopsy → new case → add Lab9-1.E01 → navigate vol2 > RECYCLER.
  2. Inside is one SID folder — its RID 1003 tells you this is the 4th created account (Mr. Evil). Open it to see renamed files like Dc1.exe (D=deleted, c=from C:, 1=first deleted), plus INFO2 and desktop.ini system files.
  3. Extract INFO2 to the case Export folder.
    📸Screenshot for your report: The RECYCLER SID folder contents including INFO2 and the Dc-named files.
  4. In Terminal, parse it:
  5. Terminal
    rifiuti ~/Desktop/Cases/FOR_LAB_009/Export/Lab9-1/INFO2 > ~/Desktop/Cases/FOR_LAB_009/Export/Lab9-1/INFO2.txt
  6. Open INFO2.txt: index number, deletion time, drive number, original path, and size per file.
    📸Screenshot for your report: The parsed INFO2.txt showing deletion times and original paths.

Task 2Parse the modern $Recycle.bin ($I files)

Vista+: each deletion makes a $R (data) and $I (metadata) pair.

  1. Add Data Source → Lab9-2.E01 → navigate to $Recycle.bin.
  2. There are three SID folders — two share a Local Computer Identifier (same machine, different users), one is from a different computer. Open the target SID.
  3. Each deleted item is a $R…/$I… pair; the $I file holds the metadata. Ctrl-select all $I files → Extract to the Export folder.
  4. Autopsy prefixes exported names with an offset, so rename before parsing:
  5. Terminal
    cd ~/Desktop/Cases/FOR_LAB_009/Export/Lab9-2/
  6. Terminal
    mv 20156-\$IEYEZMZ.exe \$IEYEZMZ.exe
  7. Manual correction

    ls first — the numeric prefix differs every run. Type the real filename shown, and use Tab completion (the \ escapes the $).

  8. Then parse the whole folder with the Vista variant:
  9. Terminal
    rifiuti-vista ~/Desktop/Cases/FOR_LAB_009/Export/Lab9-2/ > ~/Desktop/Cases/FOR_LAB_009/Export/Lab9-2/Index.txt
  10. Open Index.txt: same facts as INFO2 but no drive-number column, plus a guess at source OS and the time zone used.
    📸Screenshot for your report: The parsed Index.txt from the $I files.

04Reference — two Recycle Bin formats

RECYCLER (XP and earlier)$Recycle.bin (Vista+)
FolderRECYCLER\<SID>\$Recycle.bin\<SID>\
Renamed asD<drive><seq>.ext (Dc1.exe)$R… (data) + $I… (index)
IndexOne INFO2 for the whole binOne $I per deleted file
Parse withrifiutirifiuti-vista
Recordsorig path, drive #, size, delete timeorig path, size, delete time (no drive #)

SID / RID attribution

  • SID = S-1-5-21-<computer id>-<RID>. The computer-id portion ties the bin to a specific machine; shared computer-ids on two SIDs mean the same machine.
  • RID: 500=Administrator, 501=Guest, 1000+=created accounts. A gap (e.g. 1000, 1002) means a created account was deleted — RIDs are never reused.
  • Reading the SID folder name is what attributes a deleted file to a user, not just a machine.

06Manual corrections & currency notes

The NDG manual was written in 2020–21. These are the places where it is wrong, inconsistent, or out of date — worth knowing before you trust a screenshot.

WhereThe manual saysWhat's actually true
RifiutiUses rifiuti / rifiuti-vistaRifiuti2 (the maintained successor) is current and handles both INFO2 and $I formats in one tool. Eric Zimmerman's RBCmd is the modern Windows equivalent. The parsed data is the same.
'$Recycle.bin = Vista+' Correct split at VistaAccurate. Note that Windows 10/11 $I files use a slightly updated format (version 2, with a variable-length original filename) — modern parsers handle it; very old rifiuti builds may not.
Export prefixAutopsy prepends an offset number to exported filesStill true in current Autopsy for bulk exports — the rename step remains necessary. The prefix value changes every export.
desktop.ini / INFO2 as 'system files'Dismisses themINFO2 is the whole point (the index); desktop.ini is genuinely just a folder-view config. Don't confuse the two.

07Making it defensible

The Recycle Bin is strong evidence of intentional deletion tied to a user — handle the attribution carefully:

  • The SID attributes to an account, not a person. A deletion under Mr. Evil's SID means that account did it — tie the account to a human with other evidence.
  • Deletion time is a real timestamp. Convert to local zone and corroborate with the timeline (Lab 14) and registry (Lab 4).
  • Emptying the bin doesn't erase everything. The data may survive in unallocated space (carve it, Lab 7); the index may be gone but artifacts remain.
  • Hash recovered files (Lab 20) and document that they came from the Recycle Bin, with their original path from the index.
On the stand

The Recycle Bin shows a file was deliberately sent there by a specific account — powerful for intent. But 'the account deleted it' is not yet 'the defendant deleted it'; close that gap with corroborating artifacts.

09Check yourself

1. What does the filename Dc1.exe tell you in a legacy RECYCLER folder?

D = the file was deleted, c = it was deleted from the C: drive, 1 = it was the first file deleted (sequence). The INFO2 index holds its original path, size, and deletion time.

2. How does the modern $Recycle.bin store deletion metadata, and which file do you parse?

Each deletion creates a $R file (the data) and a matching $I file (the metadata index). You parse the $I files — with rifiuti-vista — to recover the original path, size, and deletion time.

3. You see RIDs 1000 and 1002 under one computer's SIDs but no 1001. What can you infer?

A created user account (RID 1001) existed and was deleted — SIDs/RIDs are never reused, so the gap marks a removed account.

4. A file was deleted under a specific user's SID. Can you conclude that person deleted it? Why or why not?

Not by itself. The SID attributes the deletion to an account, not a human. You need other evidence (login records, context) to tie the account to a specific person.

Recycle Bin Forensics

Overview — what this lab is really teaching

A deleted file in the Recycle Bin isn't really deleted — Windows renames it and keeps an index of where it came from and when it was deleted, tied to the user who deleted it. This lab parses both the old RECYCLER (XP and earlier) and the modern $Recycle.bin (Vista+) with the Rifiuti tool.

The through-line is attribution by SID: each user's deleted files live in a folder named for their Security Identifier, so the recycle bin tells you not just what was deleted, but by whom.

Reading the SID

S-1-5-21-<computer id>-<RID>. The RID identifies the user: 500 = Administrator, 501 = Guest, 1000+ = user-created. SIDs with the same computer-id come from one machine; a different computer-id means a drive moved between machines.

Walkthrough

Task 1 — The old RECYCLER (INFO2)

1 Open the XP image and find the user's SID folder

New case, add Lab9-1.E01. The presence of Documents and Settings and RECYCLER marks a pre-Vista OS. Inside RECYCLER, the SID folder (ending -1003) is the user's — here, Mr. Evil's. RID 1003 ⇒ the 4th non-system account.

2 Decode the deleted-file naming

Files renamed as Dc1.exe: D = deleted, c = deleted from the C: drive, 1 = first deleted. The real index is INFO2. Export it to Export/Lab9-1.

3 Parse INFO2 with Rifiuti

In a terminal:

csi@csi:~$ rifiuti ~/Desktop/Cases/FOR_LAB_009/Export/Lab9-1/INFO2

redirected to a text file, then open it with gedit. Columns: index, deleted time, drive number, original path, and size.

The parsed INFO2 showing deleted files with their original paths and deletion times.

Task 2 — The modern $Recycle.bin

4 Open the Win10 image and the SID folders

Add Lab9-2.E01. A Users folder + $Recycle.bin marks Vista+. Multiple SID folders appear — two share a computer-id (same machine, different users), one differs (a drive from another computer).

5 Export the $I index files and rename them

Each deleted file is a $R… with a matching $I… index. Export the $I files. Autopsy prefixes them with an offset on bulk export, so rename each back (the mv 20156-\$IEYEZMZ.exe \$IEYEZMZ.exe pattern) so Rifiuti recognizes them.

Linux is case- and character-sensitive

The \$ escapes the dollar sign; use Tab to auto-complete the exact names. Copy/paste the commands carefully.

6 Parse the folder with rifiuti-vista

Run rifiuti-vista against the folder (not a single file), redirect to Index.txt, open it. Same columns as before minus the drive number; it also guesses the OS and lists the timezone of the reported times.

13 Now that you are in the RECYCLER folder, you can see that there is 1 main folder inside the directory, as highlighted below. This folder stores recycled files for each user. The name of the folder is used to identify the user and is called a Security Identifier or SID. The SID is unique and will never be recycled even after the associated user is deleted. The SID can be broken down to provide details that uniquely identifies a computer as well as its user. The following table provides a breakdown of the SID seen below. S This character is an identifier that indicates that the value is an SID. It is always S. 1 This character denotes the revision level of the SID specification and is normally 1. 5 This character is called the Identifier Authority Value and defines the authority that created the SID. This value is normally 5. 21-2000478354- This value is the domain or Local Computer Identifier and is used to 688789844- uniquely identify the computer that created this identifier. 1003 This is the Relative Identifier (or RID) and is used to identify the user of the computer. RIDs come in 2 main types. The first is the RID that is created automatically by the system, and is always in the 500 range. Some examples are System Administrator, which is RID 500, and Guest, which is RID 501. The second type of RID is the one for user accounts that are created by the user or certain programs; these users' RIDs will always be 1000 or higher. If a user account is deleted and a new one created, the RID will not be recycled. This is a good way to determine if previous user accounts existed on a computer. In this instance, the RID 1003 indicates that this is the 4th non-system user account.

Why it matters in court

The recycle bin attributes deletion

Finding a deleted file matters more when you can say who deleted it, from where, and when. The SID folder + index give you all three — and a foreign computer-id can even prove a drive was used on another machine.

  • User attribution via SID/RID.
  • Original path + deletion time reconstruct intent and timeline.
  • Cross-machine evidence when a SID's computer-id doesn't match the host.

Course relevance

Part of Module 5/9. Know the RECYCLER vs $Recycle.bin structures, SID/RID decoding, and which Rifiuti variant parses which index.

Check yourself

1. A deleted file is named Dc1.exe. What do the characters tell you?

D = it was deleted; c = it was deleted from the C: drive; 1 = it was the first file deleted (sequence).

2. How does the recycle bin let you attribute a deletion to a specific user?

Deleted files are stored in a folder named for the user's SID; the RID portion identifies the account.

3. You find a SID folder whose computer-id doesn't match the host machine. What might that indicate?

The drive (or those recycle-bin entries) came from a different computer — evidence the volume was used on another machine.

4. Which tool parses an XP INFO2 file versus a Vista+ $I file?

rifiuti for INFO2 (XP and earlier); rifiuti-vista for the $I index files (Vista and later).

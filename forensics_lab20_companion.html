Overview — what this lab is really teaching

Hashing is the mathematical backbone of forensics. A hash is a fixed-length fingerprint of a file's content; change one bit and the fingerprint changes completely. This lab generates file hashes several ways, then builds a hash set and uses it in Autopsy to find known files by content regardless of their names.

The key realization: because a hash ignores filename and metadata, renaming or re-extensioning a file can't hide it from a hash match. That's how you catch stolen IP or contraband that's been disguised.

Tools & environment

WinOS: FTK Imager (export a file-hash list), Hasher (multiple algorithms), Autopsy (Hash Lookup ingest with a custom hash set).

AlgorithmNote
MD5Old, fast, collision-weak — still fine for hash-set matching
SHA-1Old but widely used; FTK Imager pairs it with MD5
SHA-256 / SHA-512Modern, strong — fewer collisions
RipeMD-256Alternative strong hash
Known vs Notable

In a hash set, Known files are the ones you want to ignore (e.g. standard OS files); Notable files are the ones you're hunting. The lab builds a Notable set.

Walkthrough

1 Export a file-hash list (FTK Imager)

Add the logical image Lab20_hashset.ad1, expand to the files, right-click the folder → Export File Hash List to E:\FOR_LAB_020\File Hash List. The CSV holds MD5, SHA-1, and the file path.

2 Hash with multiple algorithms (Hasher)

Run Hasher, confirm SHA-1/SHA-256/SHA-512/RipeMD-256 in Options, Select Folder → the Lab20 files, and Save results > To Excel. Compare against the FTK list — same content, same hashes, regardless of which tool produced them.

3 Build a hash set in Autopsy

New case, add Lab20_FEF.E01 (UTC), enable Hash Lookup → Global Settings > New Hash Set (Lab20Hashset, type Notable). Add Hashes to Hash Set → paste the MD5 column from your exported list → OK.

4 Find the matches

Run the ingest. Under Hashset Hits > Lab20hashset you'll see 11 hits — files on the image whose content matches your set. Click them: the names differ from what you hashed (some have no extension at all), yet the content is identical. Hashing saw through the disguise.

Why this is powerful

You can prove a file is a specific known file — stolen source code, a contraband image — even after someone renamed it or stripped its extension. The match is on content, which can't be faked without changing the file itself (and thus the hash).

Why it matters in court

Hashing is proof, not inference

A matching hash is near-conclusive that two files are identical in content. That underpins image integrity (Lab 01) and lets you identify disguised files with mathematical confidence — a rare thing in evidence.

  • Integrity — the foundation of admissible images.
  • Identification — known-file matching despite renaming.
  • Avalanche effect — any tampering is immediately visible as a changed hash.

Course relevance

Central to Module 9: Analysis and Validation. Know hash algorithms and their strengths, hash sets (Known vs Notable), content-based matching, and the avalanche effect.

Check yourself

1. A suspect renamed an incriminating file and removed its extension. Why can't that hide it from a hash set?

A hash is computed over the file's content, not its name or extension, so a content match in the hash set flags it regardless of what it's called.

2. In a hash set, what's the difference between Known and Notable files?

Known files are ones to ignore (e.g. standard OS files); Notable files are the ones you're hunting for.

3. What is the avalanche effect and why does it matter forensically?

Changing even one bit of a file produces a completely different hash, so any tampering is immediately evident when hashes no longer match.

4. Which hash does Autopsy's Add Hashes to Hash Set expect you to paste?

MD5 hashes, one per line.

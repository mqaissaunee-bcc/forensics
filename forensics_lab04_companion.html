Overview — what this lab is really teaching

The Windows registry is a hierarchical database of settings — and a treasure chest of forensic artifacts. It records files a user opened, URLs they typed, programs they ran and how often, USB devices ever plugged in, the last clean shutdown, and more. This lab locates the registry hives, exports them, and parses them with RegRipper.

The mental model: the registry is folders (keys) holding files (values). Many keys keep an MRU (Most Recently Used) order, and each key has a LastWrite time that usually equals when its top item was last touched.

Tools & environment

On WinOS: FTK Imager to locate and export the hives from a prepared image, and RegRipper (keydet89) to parse a hive into a readable text report using profile-specific plugins.

Walkthrough

Task 1 — Locate & export the hives

1 Load the evidence image

In FTK Imager, Add Evidence Item > Image File and open C Drive.E01 (Desktop > Toolbox > Datasets > Lab4). Expand to root.

2 Export the per-user hives

Per-user hives live in the profile. Export NTUSER.DAT (and its .LOG* files) from Documents and Settings > IEUser, and UsrClass.dat from IEUser > Local Settings > Application Data > Microsoft > Windows, into E:\FOR_LAB_004\Registry_Files.

Export the logs too

The .LOG transaction files hold changes not yet merged into the hive. On a live system UsrClass.dat is often the only hive you can copy directly.

3 Export the system-wide hives

SAM, SECURITY, SYSTEM, and SOFTWARE live together in Windows\System32\config (with no file extension). Export all four and their logs to Config_Registry_Files.

On a live system you'd use Obtain Protected Files

FTK Imager's File > Obtain Protected Files > Password recovery and all registry files exports locked hives from a running machine. The lab shows the option but cancels it, since you're using an image.

Task 2 — Parse with RegRipper

4 Rip each hive to a report

In RegRipper, set the Hive File, a Report File path, and the matching Profile (e.g. ntuser for NTUSER.DAT), then Rip it. Repeat for SAM, SYSTEM, SOFTWARE, SECURITY, and UsrClass.

Match the profile to the hive

RegRipper runs profile-specific plugins. Choosing the wrong profile produces errors or empty output. "Plugins completed with errors" is normal — check the log if a specific artifact is missing.

Task 3 — Read the artifacts

5 NTUSER.DAT — user activity

In the report, find Comdlg32 (Open/Save & LastVisited MRU — files opened/saved in dialog boxes), RecentDocs (recently opened documents, by type), TypedURLs (URLs typed in IE, URL1 always newest), and UserAssist (programs run, with run counts and last-run times).

Reading MRU order

A letter/number precedes each MRU value. The item at the top was used most recently; the letter tells you the order it was first added. Times are UTC/Zulu — convert for your timezone.

6 SAM — accounts

Under User Information: each username with its RID (500 = Administrator, 501 = Guest, 1000+ = user-created), plus password-reset date, account type, login count, and last failed login. A missing RID in the sequence can indicate a deleted account.

7 SYSTEM — the machine

Search ComputerName (hostname), the Network Key/NIC configuration (adapters, assigned IPs via GUIDs), ShutdownTime (last clean shutdown), and USBStor (every USB device ever connected — vendor, serial, last connect time).

📸 Screenshot for your report

The USBStor key showing a connected USB device's vendor ID, serial, and last-connected time.

8 SOFTWARE — what's installed

Default Browser Check, SystemRestore (DisableSR=1 means off; shadow copies are a goldmine when it's on), and WinNT_CV (product name, build, registered owner, install date).

The comdlg32 stands for Common Dialogue and is a registry key that contains the list of LastVisitedMRU (Most Recently Used) and OpenSaveMRU files. The LastWrite Time is highlighted as item 2 and reflects the date and time the registry key was last updated and is normally the same date and time that the item at the top of the list was opened. The parsed registry files will show a 'Z' when referencing time. This indicates Zulu time, generally as a term for Universal Coordinated Time (UCT).

3 As you can see in the User Information registry key, each username is listed. The number beside the username highlighted below is known as a relative identifier (RID) and is unique for each account. Every time an account is created, it gets a new RID. If an account is deleted, then the associated RID will be discarded and will never be reused. It can therefore be used to determine if user accounts were deleted. RIDs are also unique in that the 500 and 501 RIDs are reserved for the built-in Administrator user account and the Guest account, respectively. Any user-created account will receive a RID of 1000 and up.

4 We can also determine if the user's password was ever reset and when by looking at the Pwd Reset Date highlighted as item 1 below. There is also the Account Type that will tell whether the user is an administrator, guest, or regular user, highlighted as item 2. Finally, the Login Count and Pwd Fail Date outline the number of times the user logged in and the last time a login failed. These are highlighted as item 3 below.

Why it matters in court

The registry corroborates

Registry artifacts rarely stand alone — they tie a user to a file, a device, or an action at a time. UserAssist + RecentDocs + a USBStor serial can place a specific user opening a specific file from a specific thumb drive.

  • Attribution. Per-user hives tie activity to an account; SAM ties accounts to RIDs.
  • Timeline input. LastWrite times and ShutdownTime feed Lab 14's timeline.
  • Convert the time. UTC errors have sunk real cases — always localize.

Course relevance

Central to Module 5: Working with Windows and CLI Systems. Know the six hives, their scope, their highest-value keys, RID ranges, and that registry times are UTC.

Check yourself

1. Which hive and key shows programs the user ran and how many times?

NTUSER.DAT, the UserAssist key.

2. A SAM report shows RIDs 500, 501, 1000, and 1002 but no 1001. What can you infer?

A user-created account (RID 1001) was likely deleted — RIDs are never reused, so the gap evidences a removed account.

3. Where would you look to prove a specific USB drive was connected, and when?

The SYSTEM hive's USBStor key, which records each device's vendor ID, serial number, and last-connected time.

4. RegRipper reports a time with a trailing Z. What must you do before testifying to it?

That's Zulu/UTC time — convert it to the evidence's local timezone.

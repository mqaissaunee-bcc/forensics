01Overview — what this lab is really teaching

Encryption and password protection are where investigations stall — a file you can see but can't read. This lab is a realistic, end-to-end encounter with that wall: first detecting protected files, then attacking them, and — importantly — following the chain of clues that leads from one to the next.

You'll use Autopsy's Encryption Detection and Extension Mismatch modules to find an encrypted PDF and a high-entropy ISO, crack the PDF's password with pdfcrack (a dictionary attack), read the cleartext to discover it's actually a hidden VeraCrypt container's password, mount the container in VeraCrypt, find a password-protected ZIP inside, and crack that with fcrackzip (comparing brute-force vs dictionary speed).

Two lessons. First, the three attack types: brute force (try everything — thorough but can take forever), dictionary (try a wordlist of likely passwords — fast when the password is common), and rainbow tables (precomputed hashes — trade storage for time). You'll feel the difference live when fcrackzip's brute force crawls and its dictionary attack finishes instantly. Second, cracking succeeds on weak, reused, human passwords — the lab's passwords are trivial on purpose; real-world recovery is often slow, hardware-intensive, and not guaranteed, which is exactly why the investigative path (finding a password written in a cracked file) often beats the computational one.

03Walkthrough

Task 1Detect protected files

Autopsy flags encryption and extension mismatches automatically.

  1. New case → add Lab19.E01 → tick Extension Mismatch Detector (Check all file types) + Encryption Detection at ingest.
  2. Results → Extracted Content → Encryption Detected: Got it.pdf (password-prompts on open). Extract it to a pdf_file folder.
  3. Encryption Suspected: Windows XP.iso — flagged for high entropy (unusually random data = likely encrypted container). Extract it to an Encrypted folder.
    📸Screenshot for your report: The Encryption Detected / Suspected results in Autopsy.

Task 2Crack the PDF (dictionary attack)

pdfcrack tests a wordlist against the PDF's protection.

  1. In Terminal:
  2. Terminal
    cd Desktop/Evidence\ Files/FOR_LAB_019/pdf_file
  3. Terminal
    pdfcrack --wordlist=/usr/share/john/password.lst Got\ it.pdf
  4. It prints the recovered user-password. Open the PDF with that password:
  5. Terminal
    xdg-open Got\ it.pdf
  6. The PDF's contents are the real clue: they mention the ISO and give a password (steal) and name VeraCrypt — an investigative lead, not a computed one.
    📸Screenshot for your report: The pdfcrack success output showing the recovered password.

Task 3Mount the VeraCrypt container

The 'ISO' is actually an encrypted volume — the PDF told you its password.

  1. Open VeraCrypt → Select File → Encrypted\Windows XP.iso → pick a slot → Mount.
  2. Enter the password from the PDF (steal) → OK (enter the admin password csi if prompted). The volume mounts like a drive.
  3. Open it: among the files is a password-protected Zip File.zip. Copy it out to a zip_file folder first — the mounted volume is writable, so work on a copy to avoid altering evidence.
    📸Screenshot for your report: The mounted VeraCrypt volume contents including the protected ZIP.

Task 4Crack the ZIP (brute vs dictionary)

Feel the speed difference between the two attacks.

  1. Terminal
    cd Desktop/Evidence\ Files/FOR_LAB_019/zip_file
  2. Brute force — start it, watch it crawl, then cancel (Ctrl+C):
  3. Terminal
    fcrackzip -b Zip\ File.zip
  4. Dictionary — near-instant because the password is weak and common:
  5. Terminal
    fcrackzip -D -p /usr/share/john/password.lst Zip\ File.zip
  6. Open the ZIP with the recovered password:
  7. Terminal
    unzip Zip\ File.zip
  8. Note the contrast: brute force was effectively endless; the dictionary hit in a second. That gap is the lesson.
    📸Screenshot for your report: The fcrackzip dictionary attack recovering the ZIP password.

04Reference — attack types and tools

AttackHowStrength / weakness
Brute forceTry every possible combination.Guaranteed eventually; infeasible for long/complex passwords (exponential time).
DictionaryTry a wordlist of likely passwords.Fast and effective on human/common passwords; fails on random ones.
Rainbow tablesPrecomputed hash lookups.Trades huge storage for speed; defeated by salting.
Mask / rule-basedSmart brute force using known patterns.Efficient when you know password structure.

Tools you met

  • pdfcrack — PDF password recovery (dictionary/brute).
  • fcrackzip — ZIP password recovery (-b brute, -D -p dictionary).
  • VeraCrypt — opens encrypted containers/volumes once you have the password.
  • The heavyweights (beyond this lab): John the Ripper and Hashcat — free, GPU-accelerated, the real-world standard.

Entropy as a detection signal

Encrypted data looks random — high entropy. Autopsy flags high-entropy files as 'Encryption Suspected' even when their extension (here .iso) lies about what they are. Pair this with extension-mismatch detection to find disguised containers.

05Where people get stuck

Most problems in this lab fall into one of these.

SymptomLikely causeFix
pdfcrack finds nothingPassword not in the wordlistDictionary only finds what's in the list. Try a bigger wordlist or brute force — and accept it may not crack.
Linux 'no such file' errorsSpaces/case in filenamesEscape spaces (Got\ it.pdf) or quote the name; Linux is case-sensitive. Use Tab-completion.
VeraCrypt won't mountWrong password or slotUse the exact password from the PDF (steal); select a free slot; provide the admin password if prompted.
Editing the ZIP changes the volumeMounted container is writableCopy the ZIP out before cracking — the mounted volume behaves like a real drive and writes persist.
Brute force never finishesThat's the pointCancel it and use the dictionary — the contrast demonstrates why attack choice matters.

06Manual corrections & currency notes

The NDG manual was written in 2020–21. These are the places where it is wrong, inconsistent, or out of date — worth knowing before you trust a screenshot.

WhereThe manual saysWhat's actually true
Tool selectionpdfcrack + fcrackzipFine teaching tools, but real work uses John the Ripper and Hashcat — GPU-accelerated and vastly faster, with huge rule/mask support. Modern PDFs/ZIPs use stronger KDFs (AES-256, PBKDF2) that laugh at a tiny wordlist.
Difficulty realismTrivial passwords, instant cracksDeliberately unrealistic. Strong, salted, high-iteration passwords can be computationally infeasible to crack. The lab's real lesson is the method and the attack-type trade-offs, not that cracking is easy.
The investigative pathFinds a password written inside a cracked fileThis is the most realistic part: in practice you recover passwords from sticky notes, password managers, browser stores, RAM (Lab 2), the pagefile (Lab 18), or reused passwords — far more often than by brute force. Look for the password before you try to compute it.
Legal authorityCracks freelyDefeating encryption may exceed your authorization and can carry legal constraints (and, for suspects, 5th-Amendment/compelled-password questions). Confirm scope and legal basis before cracking in a real case.

07Making it defensible

Cracking is adversarial and uncertain — document the method and claim only what you achieved:

  • Document the attack. Which tool, which attack type, which wordlist, how long. A recovered password's provenance matters.
  • Work on copies. Especially inside a mounted container — never alter the original evidence while attacking it.
  • Don't overpromise. Strong encryption may be unbreakable in any reasonable time. 'I was unable to recover the password' is a legitimate, honest outcome.
  • Prefer recovery over cracking. A password found in RAM, the pagefile, a browser store, or (as here) a cracked file is faster, more reliable, and easier to explain than a brute-force success.
On the stand

Expect questions about method and certainty: how did you get the password, could you have altered the file, is the recovered content reliable? Document the attack, show you worked on copies, and be candid that cracking can fail — honesty about limits is itself credibility.

09Check yourself

1. Contrast a brute-force attack with a dictionary attack. When is each the right choice?

Brute force tries every possible combination — guaranteed eventually but infeasible for long/complex passwords. A dictionary attack tries a wordlist of likely passwords — fast and effective against human, common, or reused passwords, but useless against truly random ones. Use dictionary first; fall back to brute force (or give up) when it fails.

2. How does Autopsy flag an encrypted file whose extension disguises it, like a container named Windows XP.iso?

By entropy. Encrypted data is highly random, so Autopsy's Encryption Detection flags high-entropy files as 'Encryption Suspected' regardless of extension — and the Extension Mismatch Detector separately catches files whose content doesn't match their extension.

3. In the lab, the password to the encrypted container wasn't computed — where did it come from, and why is that realistic?

It was written in the contents of the cracked PDF. This mirrors real investigations, where passwords are far more often recovered from notes, password managers, browser stores, RAM, the pagefile, or reuse than by brute force — look for the password before trying to compute it.

4. Why shouldn't you promise an investigator you'll recover a given password?

Strong, salted, high-iteration encryption can be computationally infeasible to crack in any reasonable time, even with GPUs and large wordlists — cracking frequently fails. 'Unable to recover' is a legitimate outcome, so overpromising sets a false expectation.

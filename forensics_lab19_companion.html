Overview — what this lab is really teaching

Encryption and password protection are the walls between you and evidence. This lab shows a realistic chain: detect protected/encrypted files with Autopsy, then crack a PDF, mount a VeraCrypt container, and crack a ZIP — using passwords you recover along the way. It introduces the main cracking approaches and why real-world cracking is hard.

Only on authorized evidence

Password cracking here is a forensic technique applied to lawful evidence in an isolated lab. The same tools used without authorization are unlawful — the context is what makes it legitimate.

Tools & environment

CSI-Linux: Autopsy (Extension Mismatch Detector + Encryption Detection modules), pdfcrack, VeraCrypt, fcrackzip.

Walkthrough

1 Detect protected files

New case, add Lab19.E01, enable Extension Mismatch Detector (Check all file types) and Encryption Detection. Under Results > Extracted Content: Encryption Detected flags Got it.pdf (password-protected); Encryption Suspected flags Windows XP.iso (high entropy = unusually random, a container signature). Export both.

Entropy is the tell for hidden encryption

Encrypted data looks random. High entropy on a file that shouldn't be random (like an ISO) is a strong hint it's actually an encrypted container.

2 Crack the PDF with a dictionary

In the terminal, cd to the exported PDF and run:

csi@csi:~$ pdfcrack --wordlist=/usr/share/john/password.lst Got\ it.pdf

It reports the recovered user-password. Open the PDF — inside, it mentions VeraCrypt and another password (steal). One piece of evidence hands you the key to the next.

📸 Screenshot for your report

The pdfcrack result showing the recovered password.

3 Mount the VeraCrypt container

Open VeraCrypt, Select File → Windows XP.iso, pick a slot, Mount, and enter steal. Open the mounted volume — it holds suspicious files, including a password-protected Zip File.zip.

Copy before you touch

A mounted container behaves like a writable drive — copy Zip File.zip out to a working folder before extracting, so you don't alter the evidence volume.

4 Crack the ZIP (brute vs dictionary)

Compare the two approaches on the copied ZIP:

csi@csi:~$ fcrackzip -b Zip\ File.zip
csi@csi:~$ fcrackzip -D -p /usr/share/john/password.lst Zip\ File.zip

Brute force (-b) grinds endlessly; the dictionary attack (-D -p) returns almost instantly because the password is weak and in the wordlist. Unzip with the recovered password.

Why real cracking is hard

Strong, unique passwords plus salting defeat dictionaries and rainbow tables, and brute force against a long password is infeasible. A dedicated cracking rig and good wordlists help, but recovery is never guaranteed — manage expectations.

Where people get stuck

SymptomCauseFix
Brute force never finishesThat's expected for anything but trivial passwordsCancel (Ctrl+C) and use a dictionary.
Wordlist path wrongTypo/usr/share/john/password.lst — mind the case and spaces.
Spaces in filename break the commandShell parsingEscape them (Zip\ File.zip) or quote the name.
VeraCrypt won't mountWrong password/slotUse the password from the PDF; pick a free slot; enter admin pw if prompted.
Edited the mounted volumeIt's writableCopy files out first; never work directly in the container.

Why it matters in court

Document the method and the authority

Recovering a password is only useful if the process is documented and the access authorized. Note the tool, wordlist, and that you worked on a copy — and preserve the original encrypted evidence unchanged.

  • Detection first — entropy/extension mismatch flags what to attack.
  • Chain the evidence — one cracked file often yields the next key.
  • Preserve integrity — copy out of mounted containers; keep originals intact.

Course relevance

Supports Module 9 and incident response. Know the three cracking methods and their trade-offs, entropy as an encryption indicator, and why strong/salted passwords resist recovery.

Check yourself

1. An ISO file shows unusually high entropy. What does that suggest and why?

That it may be an encrypted container — encrypted data looks random, so high entropy on a file that shouldn't be random is a strong indicator of hidden encryption.

2. Why did the dictionary attack crack the ZIP almost instantly while brute force ran forever?

The password was weak and present in the wordlist, so the dictionary found it immediately; brute force must try combinations exhaustively, which is infeasible for anything non-trivial.

3. You mount a VeraCrypt volume and find a file of interest. Why copy it out before extracting?

A mounted container acts like a writable drive; working in it alters the evidence volume. Copying out preserves the original.

4. What two defenses make password cracking impractical in the real world?

Strong, unique passwords (defeating dictionaries/brute force) and salting (defeating rainbow tables).

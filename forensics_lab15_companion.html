Overview — what this lab is really teaching

IoT devices — smartwatches, smart speakers — quietly record intimate detail: health stats, locations, Wi-Fi passwords in plaintext, voice-command settings, account IDs. This lab examines two: a Samsung smartwatch and an Amazon Echo Dot, pulling SQLite databases and config files and reading them in DB Browser for SQLite.

The recurring theme is attribution and corroboration: a watch's health profile and a speaker's Wi-Fi history can tie a person to a device, a device to a network, and a network to a place and time — often corroborating evidence from a phone or computer.

Tools & environment

WinOS: FTK Imager to browse the ext4 images and export files, DB Browser for SQLite to read the databases.

IoT timestamps are usually Unix/epoch

In DB Browser, right-click a time column → Edit display format → Unix epoch to date or Java epoch (milliseconds) to date depending on the table.

Walkthrough

Task 1 — Samsung smartwatch

1 Confirm it's Android and find media

Load Lab15-1.img in FTK Imager — the ext4 file system signals Android. The media folder holds synced images; the hidden .thumb folder keeps thumbnails that may outlive deleted originals.

2 Export the databases

From apps: export .shealth.db, .wemail.db, and .favorite_apps.db (plus their -journal files) to E:\FOR_LAB_015\Exports\Lab15_1.

3 Read them in DB Browser

.shealth.db → shealth_profile (convert birthday/timestamp from epoch), shealth_pedometer_history (steps/distance/calories), shealth_heartrate_log (avg/min/max heart rate). .wemail.db → EmailAccountInfo (the user's email) and EmailNotiInfo (notification title, body, sender). .favorite_apps.db → app_item (MRU apps).

Task 2 — Amazon Echo Dot

4 Read the Wi-Fi config in plaintext

Load Lab15-2.E01, open the userdata ext4 partition. misc\wifi\wpa_supplicant.conf shows, in plaintext, the device codename (full_biscuit), serial/model/OS, and the last Wi-Fi SSID + passphrase + last-connect time. networkHistory.txt (view as Hex → text) adds BSSIDs, auth method, and gateway/AP MACs.

Plaintext Wi-Fi = powerful attribution

A stationary router's SSID + the last-connect time place the device within range at a specific moment — and users reuse passphrases, so that credential may unlock other services.

📸 Screenshot for your report

The wpa_supplicant.conf showing the SSID, passphrase, and last-connect time.

5 Wake word and account

The wake-word op.cfg.json (wake = COMPUTER, stop = STOP, plus sleep duration) can test a user's knowledge of the device. Export map_data_storage_v2.db and read the accounts table for the Amazon display_name — the account ID tying the device to its owner and cloud data.

Where people get stuck

SymptomCauseFix
Dates are huge numbersUnix/Java epochRight-click column → Edit display format → the matching epoch option.
Wrong epoch conversionSeconds vs millisecondsWatch tables often use Java epoch (ms); try that if Unix looks wrong.
Can't see .thumb / hidden filesDot-prefixed on AndroidFTK Imager shows them; look for the leading dot.
networkHistory.txt unreadableNot plain in FTK Imager's default viewSwitch to Hex view, then Show text only / Fit to window.
Journal file matters?SQLite -journal holds pending changesExport it alongside the .db for completeness.

Why it matters in court

IoT corroborates the human story

A watch says the wearer's heart rate spiked while running at a time; a speaker says the device was on a named Wi-Fi network at a place. Alone each is a data point; together with phone/computer evidence they build a corroborated picture of a person's movements and actions.

  • Physical + behavioral attribution from health and usage data.
  • Location via Wi-Fi and connect times.
  • Cloud pivot — the account ID opens further (advanced) cloud analysis.

Part of Module 12: Mobile Device Forensics and the Internet of Anything. Know ext4 = Android, SQLite reading, epoch conversions, and the attribution value of IoT artifacts.

Check yourself

1. An image uses the ext4 file system. What does that tell you about the device?

ext4 is used by Linux and Android, so the device is almost certainly running Android (as these IoT devices do).

2. Why is plaintext Wi-Fi data in wpa_supplicant.conf so valuable?

The SSID plus last-connect time places the device within range of a (often stationary) router at a specific time, and users frequently reuse the passphrase on other services.

3. A watch time column shows a 13-digit number. Which epoch conversion is likely correct?

Java epoch in milliseconds (Unix epoch is seconds, ~10 digits). Use 'Java epoch (milliseconds) to date'.

4. How can a smartwatch's health and heart-rate data corroborate other evidence?

It attributes the device to a wearer (age/DOB/height/weight) and correlates activity (e.g. elevated heart rate during a run) with times, supporting or contradicting a claimed sequence of events.

Overview — what this lab is really teaching

If any device tells a person's story, it's their phone. This lab examines a physical image of an Android phone in Autopsy, mining databases and config files for device identity, email, navigation history, Wi-Fi, SIM data, calls, messages, and installed apps.

The headline lesson is why you always prefer a physical extraction: like a physical disk image, it includes deleted space, so it recovers far more than the logical/advanced-logical extractions many phones restrict you to.

Walkthrough

1 Create the case with phone modules

New case (FOR_LAB_016), add Lab16.001, enable Exif Parser and Android Analyzer. Let ingest finish. Expand vol15 (the data partition).

2 Device identity & settings

settings.db → System (sound, airplane, driving mode) and secure (Bluetooth, data roaming, non-market app installs — a compromise indicator; lock-screen disabled flag; enable_facelock). checkin.xml → the phone's IMEI and the associated Gmail account.

IMEI vs serial number

The IMEI uniquely identifies the handset and — unlike a serial — is transmitted to the carrier during calls/SMS, so it ties the physical phone to network records.

3 Email, navigation, Wi-Fi, SIM

mailstore…db → messages (ids, from/to, convert dateSentMs/dateReceivedMs, subject, snippet) and attachments (filenames/paths). da_destination_history → one rich row with navigation start/end coordinates, destination address, and time. wpa_supplicant.conf → Wi-Fi SSIDs + encryption + passphrase and the device model/manufacturer/serial. SimCard.dat → ICCID, phone number, operator, country, SIM-change time.

Results > Extracted Content: Call Logs (to/from numbers, start/end times, direction, contact name), Installed Programs (name + install date — note the social apps), and Messages (SMS vs MMS, direction, read status, thread id, body, numbers).

Why it matters in court

The phone ties the person to everything

IMEI and the Gmail/SIM data attribute the handset; navigation history places the owner; messages and calls establish communication; installed apps and settings show capability and state. A physical image preserves it all, including what the user tried to delete.

  • Attribution via IMEI + account + SIM.
  • Movement via Maps navigation history.
  • Prefer physical for completeness and defensibility.

Course relevance

Core to Module 12: Mobile Device Forensics. Know physical vs logical, IMEI vs serial, Android data locations, and the parsed-artifact categories.

Check yourself

1. Why always prefer a physical extraction of a phone when the device supports it?

A physical image, like a physical disk image, includes deleted/unallocated space, so it recovers far more than logical extractions — and lets others re-examine the same data.

2. What's the forensic difference between a phone's IMEI and its serial number?

The IMEI uniquely identifies the handset and is transmitted to the carrier during calls/SMS, tying the device to network records; a serial number is not transmitted that way.

3. Which database and table would you check to reconstruct where the user navigated?

The Maps database da_destination_history, destination_history table — it holds start/end coordinates, the destination address, and the time.

4. The 'secure' settings show non-market app installs enabled. Why might that matter?

It allows sideloading apps from outside the official store, which is a common precondition for device compromise or installation of suspicious software.

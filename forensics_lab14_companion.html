Overview — what this lab is really teaching

Individual artifacts answer 'what'; a timeline answers 'what happened, in what order.' This lab uses Autopsy's Timeline to sort every dated artifact chronologically and then reconstruct a sequence of events — the forensic storytelling that ties a case together.

The scenario makes it concrete: a user claims they don't know how illicit images appeared on their machine. You use the timeline to show the files were created seconds after a browser accessed them — demonstrating they were downloaded, not planted.

Tools & environment

WinOS, Autopsy with the Recent Activity module (to populate web history) and the built-in Timeline feature.

Walkthrough

1 Create the case and run ingest

New case (FOR_LAB_014_Timeline) under E:, add Lab14.E01 with the UTC timezone, enable Recent Activity, and wait for ingest to finish — an incomplete ingest means an incomplete timeline.

2 Tag the files of interest

Browse to Documents and Settings > Fred > My Documents > My Pictures (the Documents and Settings folder tells you it's XP-era). Select the five GIFs, note their created/accessed/modified times, and Add File Tags > Bookmark. Sorting by Created Time shows they all landed within ~30 minutes on 2006-06-08.

3 Open Timeline and locate the window

Launch Timeline, switch to GMT/UTC, filter to Must be tagged to confirm the files sit in the 2006 bar, then drill 2006 → June → the 8th.

4 Reconstruct the sequence

Clicking into 2006-06-08's file activity and scrolling to ~07:56:04 shows the GIFs being created. Backtrack to ~07:55:39 and you see Temporary Internet Files activity — a browser was open. Switch the bar to web activity and (back in Local time) you find the browser accessed m001.gif at 07:55:53 — 11 seconds before the file was created at 07:56:04.

That 11-second gap is the finding

Browser interaction immediately before file creation = the file was downloaded via the browser. The event order, visible only in a timeline, is what disproves the 'I don't know how it got there' claim.

5 Confirm the source

Click the 07:56:04 event: the Data Interpreter shows the path (…/Fred/My Documents/My Pictures/m001.gif), the browser name and user, and the source index.dat (old IE history). Conclusion: the user browsed www.mickey-mouse.com and downloaded the files.

Why it matters in court

Sequence defeats 'I don't know how it got there'

A timeline turns scattered timestamps into a narrative. Showing that a browser accessed a file seconds before it was created is far more persuasive than a bare creation date — it demonstrates intent and mechanism.

  • Order is argument. Which event came first is the forensic story.
  • Timezone discipline keeps the narrative defensible.
  • Corroboration — timeline weaves together file, web, and registry evidence.

Course relevance

A capstone technique spanning Modules 5, 9, 11. Know MACB times, correlating web events with file creation, and rigorous timezone handling.

Check yourself

1. A file was created at 07:56:04 and the browser accessed it at 07:55:53. What does the 11-second gap suggest?

The file was downloaded through the browser — the browser interaction immediately precedes the file's creation, indicating the user obtained it, not that it was planted.

2. Why is consistent timezone handling critical in timeline analysis?

Mixing UTC and local time silently misorders events and produces wrong conclusions; everything must be read in one known zone.

3. What's more persuasive forensically — a file's creation timestamp alone, or its place in a sequence of events?

Its place in the sequence. Order (what happened just before and after) demonstrates mechanism and intent in a way a lone timestamp cannot.

4. Why wait for the Recent Activity ingest to finish before opening Timeline?

An unfinished ingest produces an incomplete timeline, so correlations (like web access before file creation) may be missing.

01Overview — what this lab is really teaching

Individual artifacts are dots; a timeline is the line that connects them. By sorting every file-system and application event by its timestamp, you can watch a sequence unfold — a website visited, a file downloaded seconds later, a picture created, a program run — and tell the story of what actually happened, in order, often answering the question an artifact alone can't: how did this get here?

You'll build a case in Autopsy, populate it with the Recent Activity module, and use the Timeline feature to work a real scenario: a user claims they don't know how certain images appeared on their machine. You'll zoom from year to month to day, filter by tagged files, and reconstruct the eleven seconds in which a browser fetched an image and the file landed on disk — turning 'I don't know how it got there' into a documented download sequence.

The method is pivoting on time: find an anchor event (a file's creation time), then look at what happened immediately before and after it across all artifact types at once. The discipline is time-zone and timestamp-type awareness — MAC times, browser epochs, and log times may all be in different zones or clocks, and a timeline built on mismatched times tells a false story. Correlation is powerful but not proof: events near each other in time are related, not necessarily causal.

03Walkthrough

Task 1Build and populate the case

A timeline is only as complete as the artifacts feeding it.

  1. New case → add Lab14.E01 → set time zone to (GMT+0) UTC → tick Recent Activity at ingest (it adds web history so the timeline isn't just file-system events).
  2. Let ingest finish before opening the Timeline — an incomplete ingest makes an incomplete timeline.

Task 2Anchor on the files in question

Start from the evidence you care about and read its timestamps.

  1. Navigate to vol2 > Documents and Settings > Fred > My Documents > My Pictures — five GIFs.
  2. Select all five, Add File Tags > Bookmark so you can filter to them.
  3. Sort by Created Time: the files were created between 07:56:04 and 08:20:40 on 2006-06-08 — within ~30 minutes. Note this window.
    📸Screenshot for your report: The five GIFs sorted by Created Time showing the ~30-minute window.

Task 3Drill down in the Timeline

Zoom from year to the exact day and confirm your tagged files live there.

  1. Open Timeline → set Display Times to GMT/UTC. Filter Must be tagged + Apply to confirm the tagged files sit in the 2006 bar.
  2. Uncheck the tag filter → double-click 2006 → June → day 08 to expand to that day's activity.
    📸Screenshot for your report: The Timeline expanded to 2006-06-08 showing the day's events.
  3. Scroll the day's events to the first file's creation at 07:56:04, then backtrack to see what preceded it.

Task 4Reconstruct the sequence

Read across artifact types to answer 'how did it get here?'

  1. Just before 07:56:04 you see activity in Temporary Internet Files — a browser was active.
  2. Switch to the web-history segment (and back to Local Time where noted): a browser interacted with m001.gif at 07:55:53, 11 seconds before the file was created at 07:56:04 at the same path.
    📸Screenshot for your report: The web-history entry for m001.gif 11 seconds before the file's creation.
  3. Click the 07:56:04 entry: the view pane shows the file path, access times, the browser name, the user, and the source index.dat.
  4. Conclusion: the user browsed www.mickey-mouse.com and downloaded m001.gif / m002.gif via the browser — the 'I don't know how it got there' claim is contradicted by the sequence.

04Reference — timeline method and pitfalls

How to work a timeline

  • Anchor on a known event (a file's creation, a login, a download).
  • Pivot: look at everything — file system, web, registry, logs — immediately before and after the anchor.
  • Zoom: year → month → day → minute. Bar charts show volume; detailed view shows individual events.
  • Filter by tag, event type, or text to cut noise.
  • Corroborate: a single artifact can be wrong; a sequence across independent artifacts is strong.

Timestamp types that feed a timeline

SourceTimestamp
File system (NTFS/FAT)MAC times: Modified, Accessed, Created (+ MFT change on NTFS).
BrowsersChrome (µs since 1601), Firefox (µs since 1970), IE index.dat.
RegistryKey LastWrite times (UTC).
Event/USN logsEvent time, USN record time.
EXIF / documentsEmbedded capture/create/modify times.
Watch out

Every one of these may be in a different time zone or epoch. Normalize to a single zone before you read the sequence, and state which zone your findings use.

06Manual corrections & currency notes

The NDG manual was written in 2020–21. These are the places where it is wrong, inconsistent, or out of date — worth knowing before you trust a screenshot.

Dataset vintageWindows XP, index.dat, Temporary Internet FilesAll legacy. Modern timelines pull from NTFS $MFT/$UsnJrnl (Lab 17), SQLite browser DBs (Lab 13), and the registry — same method, newer sources. index.dat is IE-only history.

07Making it defensible

A timeline is a narrative, and narratives can mislead — so build it rigorously and claim it modestly:

  • Normalize and document the time zone. One zone, stated explicitly. A mismatched zone invalidates the sequence.
  • Correlation is not causation. 'A browser touched the file 11 seconds before it was created' is a strong, documented sequence — say that, not 'the user definitely intended to download it,' unless other evidence supports intent.
  • Watch for timestamp tampering. Timestomping and disabled access-time updates can distort a timeline; cross-check $FILE_NAME vs $STANDARD_INFORMATION and other artifacts.
  • Reproducibility. Your timeline should be rebuildable from the same image with the same tool and settings — that's what makes it defensible.
On the stand

The timeline is often the clearest story you can tell a jury — which is exactly why the defense attacks its foundations (zone, epoch, tampering). Pin every assumption, cite the independent artifacts behind each step, and distinguish the documented sequence from any inference of intent.

09Check yourself

1. What is the core analytical technique of timeline analysis?

Pivoting on time: anchor on a known event (like a file's creation time), then examine what happened immediately before and after it across all artifact types at once — file system, web, registry, logs — to reconstruct the sequence.

2. In the lab scenario, what sequence contradicted the user's claim that they didn't know how the images appeared?

A browser interacted with m001.gif at 07:55:53, and the file was created at the same path 11 seconds later at 07:56:04 — showing the image was downloaded via the browser from www.mickey-mouse.com, not placed there unknowingly.

3. Why is getting the time zone right the single most important discipline in timeline work?

Different artifact sources record times in different zones and epochs (MAC times, Chrome/Firefox epochs, registry UTC). If you don't normalize to one documented zone, events will appear out of order and the timeline will tell a false story.

4. Your timeline shows two events seconds apart. What can you claim, and what should you be careful not to claim?

You can claim a documented temporal sequence — event A preceded event B by a known interval. You should be careful not to assert causation or intent from proximity alone; correlation isn't proof, so support any claim of cause/intent with additional evidence.

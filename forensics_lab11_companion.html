01Overview — what this lab is really teaching

Every photo a smartphone takes carries a hidden dossier: EXIF metadata recording the exact camera make and model, the date and time the shot was taken, exposure settings, and — often — GPS coordinates pinpointing where. This metadata can place a specific device in a specific location at a specific moment, or tie a photo to a particular phone. Separately, Windows caches shrunken copies of images in Thumbs.db, which can retain a thumbnail of a photo even after the original is deleted.

You'll extract and read EXIF data with ExifTool on a set of smartphone photos, then carve JPEG thumbnails out of a Thumbs.db file by hand in HxD (the same header/footer technique from Lab 7).

Two forensic payoffs. First, EXIF is attribution and geolocation in one file — 'this Google Pixel 3 XL took this photo at these coordinates at this time.' Second, the thumbnail cache defeats deletion: a user who deletes incriminating photos may leave recoverable thumbnails behind in Thumbs.db. Both are high-value, and both come with caveats — EXIF can be stripped or edited, and a timestamp is only as trustworthy as the device clock that set it.

03Walkthrough

Task 1Extract EXIF with ExifTool

One command dumps the full metadata dossier.

  1. On DEFT, open LXTerminal and go to the photos:
  2. Terminal
    cd Evidence_Files/FOR_LAB_011/Pics
  3. List the files (ls): four JPEGs and a database file.
  4. Dump one photo's EXIF to screen, then to a text file for easier reading:
  5. Terminal
    exiftool IMG_001.jpg
  6. Terminal
    exiftool IMG_001.jpg -w txt
  7. Open IMG_001.txt in gedit. Read: file info, camera make/model (e.g. Google Pixel 3 XL), software/resolution, Date/Time Original (when the shot was taken), and at the bottom, GPS latitude/longitude/altitude.
    📸Screenshot for your report: The EXIF text showing camera make/model and Date/Time Original.
  8. Repeat for IMG_002–004; note each photo's capture date/time and GPS.
    📸Screenshot for your report: The GPS coordinates block at the bottom of an EXIF report.

Task 2Carve thumbnails from Thumbs.db

Thumbs.db hoards shrunken copies of images — recoverable even if originals are gone.

  1. Switch to WinOS. Open Thumbs.db (in FOR_LAB_011\DB_File) in HxD.
  2. Find the JPEG header FF D8 FF E0 → note start offset (0xA18).
  3. Find the footer FF D9 → note the end offset (0x6E38).
  4. Edit > Select block between the offsets → Save selection → pic1.jpg. Open it — it's a thumbnail of IMG_001.JPG.
    📸Screenshot for your report: The carved thumbnail open, matching one of the original photos.
  5. Continue Find (Forward) for more header/footer pairs and carve each thumbnail. Even deleted-original images can survive here.

04Reference — EXIF fields and thumbnail caches

High-value EXIF fields

FieldForensic value
Make / ModelDevice attribution — which phone/camera took it.
Date/Time OriginalWhen the shot was captured (vs file-system dates). Device-clock dependent.
GPS Latitude/Longitude/AltitudeWhere it was taken — geolocation.
SoftwareFirmware/app version — can corroborate the device.
Flash / Orientation / ExposureScene details, sometimes corroborative.

Thumbnail caches across Windows

  • Thumbs.db (XP-era, and per-folder in some configs): one file per folder, holds JPEG thumbnails. Carve by FF D8 FF E0 / FF D9.
  • thumbcache_*.db (Vista+): centralized per-user in AppData\Local\Microsoft\Windows\Explorer, multiple sizes. Parse with Thumbcache Viewer.
  • The key property: a thumbnail persists after the original is deleted, because Explorer cached it when the user viewed the folder as thumbnails.

06Manual corrections & currency notes

The NDG manual was written in 2020–21. These are the places where it is wrong, inconsistent, or out of date — worth knowing before you trust a screenshot.

WhereThe manual saysWhat's actually true
Thumbs.db vs thumbcacheFocuses on Thumbs.dbThumbs.db is largely XP-era. Windows Vista onward uses centralized thumbcache_*.db files per user — same evidentiary value (thumbnails survive deletion), different location and tool (Thumbcache Viewer). Modern exams look there.
ExifTool scopeUsed only on photosExifTool reads metadata from hundreds of formats — PDFs, Office docs, video, audio. It's the de facto standard and far outclasses the Lab 8 MetaExtractor. Learn it as a general metadata tool.
GPS reliabilityPresents GPS as locating the photoGPS EXIF is the device's recorded fix — it can be absent, imprecise, stale, or spoofed, and it reflects the device's position, not necessarily the subject's. Corroborate.
Timestamp trustTreats Date/Time Original as authoritativeIt's only as accurate as the device clock — wrong time zone or a reset clock throws it off. Cross-check against other artifacts.

07Making it defensible

EXIF and thumbnails are compelling but editable and clock-dependent — qualify them:

  • EXIF can be edited or stripped. Present it as 'the metadata recorded by the device', and note that metadata can be altered. Corroborate device attribution with other artifacts (registry, the actual device).
  • GPS is the device's fix, not necessarily ground truth. It can be off, stale, or spoofed. State coordinates with appropriate caution.
  • Capture time depends on the device clock. Verify the clock/zone before stating when a photo was taken.
  • A thumbnail is not the original. It proves the image was viewed on this machine and cached — strong, but distinct from proving the full-resolution original was stored.
On the stand

A geotagged photo seems to place someone somewhere — but EXIF is defense-editable, and GPS/clock can be wrong. Lead with what the metadata records, back it with corroboration, and don't overstate certainty of place or time.

09Check yourself

1. Name three distinct things EXIF metadata can establish about a photo.

Device attribution (camera make/model), when it was taken (Date/Time Original), and where (GPS coordinates). It can also carry software version, exposure, and orientation.

2. How can a Thumbs.db file provide evidence of a photo that no longer exists on the drive?

Windows caches a shrunken thumbnail when the user views a folder as thumbnails. That cached copy persists even after the original is deleted, so you can carve the thumbnail out of Thumbs.db by its JPEG signature.

3. Why should you be cautious stating that a geotagged photo proves a person was at a location?

GPS EXIF records the device's fix, which can be absent, imprecise, stale, or spoofed, and reflects the device's position — not necessarily the subject's. EXIF can also be edited. So it's corroborative, not conclusive.

4. On a modern Windows 10 machine, where would you look for cached thumbnails instead of Thumbs.db?

In the centralized per-user thumbcache_*.db files under AppData\Local\Microsoft\Windows\Explorer, read with a tool like Thumbcache Viewer.
